# Mira 学生学习空间与 OpenMAIC 上线架构

## 1. 产品目标

学生打开网页后，应进入一节可持续学习、可恢复进度、可验证掌握证据的课程，而不是一个题目弹窗，也不是 OpenMAIC 编辑器的公开副本。

一节正式课程至少包含：

1. 概念导入；
2. 老师讲解；
3. 已验证的示范；
4. 两次引导互动；
5. 两次独立检查；
6. 纠错反馈与复盘；
7. 已审核的教师旁白、字幕和必要媒体；
8. 可恢复的课堂游标、学习报告和掌握证据。

学生端只展示已经进入 active catalog release 的课程。生成成功、课件编译成功和正式发布是三个不同状态。

## 2. 系统职责

```text
授权教材、课程标准或原创资料
  -> MinerU 文档解析与来源快照
  -> Mira 版本化课程边界
  -> OpenMAIC + Kimi 候选内容与独立求解
  -> Mira 确定性答案、年级、范围和教学法校验
  -> Mira 受控 LessonPackage、教师音频与媒体审核
  -> 完整目录原子发布
  -> 后台生成完整 OpenMAIC 课堂并人工回放审核
  -> 学生 Web 进入完整互动课堂
  -> Mira 独立检测、掌握度、恢复与报告
```

Mira 是以下数据的唯一权威：

- 学生身份与家庭边界；
- 年级、学科、能力进阶和前置关系；
- 正确答案、评分、掌握度与学习报告；
- 教师档案、教师偏好和可公开媒体；
- 课程目录发布、退役和历史版本。

OpenMAIC 的职责是：

- 把固定课程边界编排成课堂大纲、场景、动作和多智能体课堂；
- 播放幻灯片、测验、视频、3D/HTML 交互、模拟实验和 PBL；
- 运行 AI 教师、AI 同学、圆桌讨论、实时白板、TTS/ASR 和教师操作；
- 在私有内容运营环境提供编辑、导出和可选 MP4 渲染能力。

浏览器不持有模型密钥，也不直接调用 OpenMAIC generation。完整课堂只运行固定提交、自托管且已经人工回放审核的 OpenMAIC 内容；未经审核的模型 HTML、脚本、媒体或课堂不会获得学生启动票据。

## 3. MinerU 的位置

MinerU 是资料解析器，不是课程生成器。它负责把 PDF、Office 文档和图片中的正文、表格、公式、OCR、图片与版面信息变成可检索的 Markdown/JSON。

MinerU 输出只能作为 `source grounding`：

- 每份资料保存来源、版本、checksum、页码和解析结果；
- 每个能力边界只引用经过授权的片段；
- 模型收到的内容受字符数、图片数和范围限制；
- MinerU 不能决定年级顺序、正确答案、课程是否发布；
- 教材原文不直接复制到学生课件，需满足授权与引用策略。

未提供或未授权教材时，课程必须明确标记为 Mira 原创能力课，不宣称同步某个教材版本。

## 4. 教师和声音

首版教师注册表固定为三位可审核的教学身份：

| 学科 | 教师 | 语言 | 教学风格 |
| --- | --- | --- | --- |
| 语文 | 小语老师 | zh-CN | 温柔引导、标准普通话 |
| 数学 | 小数老师 | zh-CN | 清晰、分步骤、停顿明确 |
| 英语 | Mia 老师 | en-US | 慢速清晰、标准英语发音 |

教师档案是版本化服务端配置，不由学生自由写 prompt。公开数据只包含头像、名称、学科、语言、风格和能力，不包含 Provider、模型、voice prompt 或存储路径。

正式旁白使用服务端 VoxCPM2 适配层：

- 支持 vLLM-Omni `/v1/audio/speech`；
- 支持 VoxCPM Python `/tts/upload`；
- 不向浏览器下发 TTS 地址或密钥；
- 不开放参考音频和声音克隆；
- 每段音频保存 checksum、字幕、教师版本和生成任务；
- 英语和拼音旁白必须人工发音审核后才可变成 `ready`；
- Provider 失败时课程保持 `media_pending`，不伪造正式音频；
- 浏览器 TTS 只允许作为明确标记的开发降级，不满足生产发布门。

## 5. 课程和课件生命周期

### 5.1 课程候选

每个能力边界固定生成五个受控对象：

- q1：示范，不计掌握度；
- q2、q3：引导互动，必须同为 `single_choice` 或同为 `sequence`；
- q4、q5：独立检查，可使用确定性数字、文本、选择或排序；
- 只有 q4、q5 首次作答都正确，才产生本节课的 mastered 证据。

候选必须通过：

- 当前 curriculumVersion 和 boundaryVersion；
- 年级、学科、允许范围、排除范围和前置能力；
- 五题唯一性和题型白名单；
- 数学表达式独立复算；
- 语文、英语独立求解一致；
- 练习答案不泄漏到讲解、提示、选项顺序或课件；
- 独立 teaching review。

### 5.2 LessonPackage

OpenMAIC 生成结构化教学意图，Mira 编译成只读、版本化的 LessonPackage：

- `teach`：老师先讲；
- `demo`：展示已验证示范；
- `guided`：真实服务端判题的互动；
- `independent`：独立检查；
- `recap`：只总结本节证据，不夸大为完全掌握。

受控模板必须与题型一致：

- `listen_tap_choice.v1`：q2/q3 都是单选；
- `match_pairs.v1`：q2/q3 都是单选，分别提交 opaque option id；
- `sort_order.v1`：q2/q3 都是排序；
- 不兼容时发布失败，不由前端猜测答案协议。

### 5.3 媒体与发布

LessonPackage 中每个必需旁白都会建立 required package asset 记录。目录激活必须同时满足：

- 课程为当前边界的 `auto_validated` 候选；
- LessonPackage 已发布且未退役；
- 必需资产全部存在；
- asset、variant、scan、moderation、transcode 全部 ready/passed；
- 所有 required review 均为 approved；
- 目录覆盖当前构建目标，无失败或缺失项目；
- 操作员执行原子 activate。

上一 active release 在新 release 成功激活后才退役。历史 session 和报告保留原课程、课件与媒体版本。

### 5.4 完整 OpenMAIC 课堂运行时

受控 LessonPackage 和正式目录发布后，独立后台 worker 才会生成完整 OpenMAIC 课堂。`today`、开始课程和其他学生请求绝不现场调用模型。

完整运行时固定为经过审计的 OpenMAIC 版本和提交，支持：

- 幻灯片、测验和视频课件；
- 3D 可视化、HTML 游戏、思维导图、在线编程和模拟实验；
- PBL、AI 教师与 AI 同学、多 Agent 圆桌讨论；
- 实时白板、语音讲解、语音输入和教师主动操作界面；
- 内容运营侧可选的 Chromium + FFmpeg MP4 课程视频导出。

生成请求只包含年级、学科、能力边界、标题、学习目标、教师风格和能力开关，不包含私有答案或 evaluator 数据。生成完成后状态为 `pending_review`；内容运营人员必须完整回放并审核事实、适龄性、Agent 对话、互动、视频、字幕和发音，之后才能标记为 `approved`。

学生进入课堂时，Mira 为当前学生、当前学习 session 和当前已发布课堂签发 60 秒一次性票据。OpenMAIC runtime gateway 将票据兑换成 HttpOnly 课堂 Cookie，并只允许访问该课堂所需的文档、媒体、PBL、对话、TTS/ASR 和测验接口。它会阻止生成、编辑器、Provider 设置、其他课堂、任意媒体代理和学生发起的 MP4 渲染任务。

OpenMAIC 内测验、游戏和 PBL 反馈属于形成性练习。学生完成沉浸式课堂后，仍需进入 Mira 的独立检测；最终答案、报告和掌握度只由 Mira 后端写入。

每节课按教学价值选择能力，不要求为了展示技术同时堆入 3D、视频、PBL 和圆桌。平台支持完整能力，与每节课必须使用全部能力是两件不同的事。

## 6. 学生 Web 信息架构

学生端正式页面包括：

- `今日学习`：今天安排、继续上课、制作中和完成状态；
- `我的学习`：最近继续、学习记录、学科筛选、收藏；
- `课程详情`：目标、教师、预计时长、历史结果；
- `课堂`：阶段路线、课件舞台、教师引导、字幕、互动和报告；
- `老师选择`：只显示当前学科的受控教师档案。

课程和媒体都从学生身份限定的 API 获取。资产下载必须验证：

- student token 有效；
- asset 属于该学生已有 session 所固定的 package；
- package 和 content hash 与 session 一致；
- asset 已完成全部发布审核；
- 文件路径位于配置的安全媒体根目录内。

## 7. 课程质量验收

每门课发布前至少检查：

- 年级和课程边界无越级；
- 一年级语文首节点为 a/o/e，而不是偏旁、声母或整体认读；
- 先教后练，示范答案不进入独立题；
- 引导互动必须发生有效状态变化，不能点击即通过；
- 错误有可执行的分层提示；
- 独立检查有真实服务端判定；
- 旁白、字幕和屏幕内容一致；
- 拼音、英语发音已人工审核；
- 390×844、1024×768、1366×768 无 CTA 裁切和嵌套滚动；
- 1–2 年级正文不小于 20px、主要触点不小于 52px；
- reduced-motion 不跳过课堂语义；
- 关闭并重开后从服务端游标恢复。

批量构建不会自动等于上线。构建报告应保存每个边界的课程、课件、媒体、审核和失败原因；抽检通过后才激活整批目录。

## 8. 运行配置原则

以下配置只存在于后端：

- Kimi/OpenAI-compatible Provider、模型和 API Key；
- MinerU Base URL 和可选认证；
- VoxCPM2 Base URL、后端类型和模型；
- 媒体存储根目录；
- 课程、课堂和媒体 worker 开关；
- 固定 OpenMAIC runtime 内部地址、学生 gateway 地址、生成 worker 和 MP4 导出开关；
- internal API token 与审核权限。

正式环境必须使用 HTTPS/WSS、私有学生认证 pepper 和受控媒体域名。学生端和家长 App 不保存模型、MinerU 或 TTS 密钥。

## 9. 明确边界

- MinerU 接入代码不代表已经获得或解析了教材；资料必须由产品方提供并确认授权。
- VoxCPM2 适配代码不代表已经生成标准发音；必须配置真实服务并完成人工审核。
- OpenMAIC 生成成功不代表课程已发布；Mira 发布门是最终权威。
- 当前目录版本是 Mira 核心能力目录，不得宣称覆盖所有地区教材、所有学期章节或与某个教材逐页同步。
- 视频、3D、PBL 和自由 HTML 不因模型能生成就直接进入儿童浏览器；只有固定 OpenMAIC runtime、当前发布课程、一次性学生票据、网关路由限制和人工回放审核同时通过后才可进入。
- 完整运行时代码接入不等于已经生成上线课程；正式生成仍需要配置模型 Provider、启动私有 runtime、完成真实课程生成和人工审核。
