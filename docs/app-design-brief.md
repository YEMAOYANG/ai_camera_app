# Mira Guardian 家长端 App Design Brief v2

更新日期：2026-05-28  
适用范围：`app-prototype-v2/` HTML 高保真原型、后续 Figma 设计、后续 Flutter 页面实现  
当前阶段目标：先验证首页视觉方向。首页方向确认后，再迁移任务首页、实时看护和全量页面状态矩阵。

## 1. v2 视觉 Thesis

v2 不再使用“状态卡堆叠 + 后台控制台”的组织方式。Mira Guardian 要像一个冷静、轻盈、可信的儿童 AI 陪伴与习惯养成 App：第一眼看到孩子今天正在练什么习惯，第二眼理解米拉如何低打扰陪伴执行，第三眼才进入任务确认、奖励、看护和设置操作。

设计方向：

- 主体布局参考 Travel APP 和 Aspen：大图主视觉、留白、横向内容卡、详情页圆角内容面板。
- AI 解释和处理反馈参考 Miquido：对话式解释卡、AI disclosure、选项 chips、轻量统计。
- 底部导航只参考 Navigation Bars UI Kit：白色浮动凹形底座、中央创建按钮、展开/收起节奏、轻选中态。
- 整体必须像真实消费级移动端 App，不像后台、不像管理台、不像线框图。

Signature move：

> Habit rhythm light path：每个核心页面先呈现“今日习惯节奏”和孩子当前主练习，再用 AI capsule 解释米拉如何陪伴、提醒和收集证据，最后给家长一个明确确认动作。

## 2. v2 Color Tokens

v2 不沿用旧版绿色 accent、网格背景和后台式灰绿系统。色彩改为冷白、冰蓝、深海墨色和少量暖橙。

| Token | Value | 用途 |
|---|---|---|
| `bg` | `#F5F8FC` | App 背景，冷白浅蓝 |
| `surface` | `#FFFFFF` | 主面板、sheet、详情内容区 |
| `surface-blue` | `#EAF3FF` | 轻信息区、AI 提示背景 |
| `surface-mist` | `#EEF4F8` | 横向卡片、日期条、弱层级区 |
| `ink` | `#14212B` | 主文字 |
| `muted` | `#697A89` | 次级文字 |
| `soft` | `#A8B7C5` | 图标未选中、弱标签 |
| `line` | `#DDE7EF` | 分割线、浅边框 |
| `primary` | `#2478FF` | 主 CTA、tab selected、关键操作 |
| `primary-deep` | `#0F4BC7` | 视频浮层、重要按钮 pressed |
| `ai` | `#6D5DF7` | AI 解释、置信度、智能建议 |
| `warm` | `#FF8A4C` | 今日重点、待处理提醒、奖励 |
| `danger` | `#E25555` | 安全告警、危险操作 |
| `warning` | `#D8922B` | 弱网、待确认、延后 |
| `success` | `#25A06A` | 在线、完成、正常 |

使用规则：

- `primary` 只用于导航选中、主 CTA 和正在发生的关键操作。
- `ai` 只用于 AI 解释，不做普通装饰。
- `danger / warning / success` 只表达状态语义。
- 不使用旧版绿色主色，不使用网格背景，不做大面积默认渐变。
- 图片区域允许用暗色 scrim 保证文字可读，但不使用毛玻璃。

## 3. v2 Typography

字体：

- 中文：`PingFang SC / HarmonyOS Sans / MiSans / system-ui`
- 英文/数字：系统字体，数字使用 `tabular-nums`

字号层级：

| Token | Size | Line Height | 用途 |
|---|---:|---:|---|
| `caption` | 11-12 | 1.35 | 状态、时间、chip |
| `body` | 14-15 | 1.55 | 卡片说明、列表说明 |
| `body-strong` | 15-16 | 1.45 | 任务名、状态句 |
| `title` | 22-26 | 1.15 | 页面标题、主卡标题 |
| `display` | 32-40 | 1.05 | onboarding/主视觉标题 |
| `metric` | 28-44 | 1.0 | 倒计时、关键数值 |

排版规则：

- 首屏标题更大胆，但只在页面顶层使用；卡片内不使用大标题。
- 页面不再全部使用“标题 + 列表卡片”结构。
- 主视觉卡内文字要短，优先状态句和下一步，不写说明书。
- AI 解释卡使用较小字号和短句，像助手反馈而不是报告正文。

## 4. v2 Tabbar 规格

参考：Navigation Bars UI Kit node `12:1117`。

结构仍保留：

```text
首页 / 任务 / + 创建 / 看护 / 我的
```

视觉规格：

- 底栏为白色浮动底座，高度约 84-92px，左右 18-22px，底部 14-18px。
- 底栏顶部中间有凹形空间承托中央创建按钮，底座不加厚重边框。
- 中央按钮直径 58-64px，默认 `primary` 蓝色，突出但不使用旧版绿色。
- 点击中央按钮后进入 open state：按钮变为白色或浅面，图标从 `+` 旋转为 `×`，上方以弧形弹出 3 个快捷动作：
  - 普通任务
  - 小书包
  - 睡前/打卡
- 选中 tab：图标填充或加粗，文字使用 `primary`，底部短 pill/indicator。
- 未选中 tab：图标和文字使用 `soft`。
- tabbar 轻盈、消费级，不像后台控制台，不使用厚边框和大阴影。

交互节奏：

- tab 切换：内容区域横向轻滑 180ms。
- 中央创建展开：按钮旋转 160ms，快捷 action 以 24px 弧形位移弹出，错峰 40ms。
- 不使用弹跳过强的动画，支持 reduced motion。

## 5. v2 页面布局策略

### 首页

旧版首页的“状态卡 + 待处理卡 + 快捷入口卡”全部废弃。v2 首页采用“今日习惯节奏台”：

1. 顶部轻 header：问候、孩子头像/设备状态、通知圆形按钮。
2. 今日主习惯卡：突出“正在练什么”，例如学习自启动、餐桌收尾、睡前自理。
3. 习惯节奏光轨：展示当前任务、下一步、休息、奖励、睡前节点，而不是任务数量或完成率。
4. 家长确认队列：任务证据、奖励申请、卡住任务和需要改规则的建议。
5. AI 陪伴解释：说明米拉说了什么、提醒了几次、为什么现在不需要家长介入。
6. 单一主 CTA：处理需要家长确认的事项；实时看护只是辅助入口。

### 任务首页

旧版任务普通列表废弃。v2 任务页采用：

1. 顶部日期横条，像 Travel/Aspen 的分类 tab。
2. 今日主任务大卡：用大面积色块/图片背景展示当前最重要任务。
3. 进度和下一步内嵌在主任务卡内，不再拆成多个小状态卡。
4. 横向模板卡：小书包、睡前、朗读、周五检查。
5. AI 建议模块：说明任务安排原因，并给出 chips 操作。
6. 创建任务 CTA 不在列表底部，改为底栏中央和主任务卡右下角小 CTA 双入口。

### 实时看护

旧版实时看护的功能面板废弃。v2 看护页采用：

1. 视频/画面主视觉占据首屏大部分区域，像详情页大图头部。
2. 视频上叠加轻量 HUD：LIVE、隐私灯、网络质量。
3. 浮动控制按钮覆盖在画面底部：截图、通话、提醒。
4. 画面下方使用圆角内容面板，承接 AI 状态解释、当前任务、事件片段。
5. 弱网/隐私/离线状态不以后台 banner 呈现，而以画面状态层 + AI 解释卡呈现。

### 告警详情

全量迁移时采用：

1. 证据大图/视频头部。
2. 内容面板从底部圆角上浮。
3. AI 解释、触发规则、处理时间线按模块分层。
4. 底部固定处理 CTA：联系孩子 / 标记已处理 / 误报。

### 我的页

全量迁移时采用：

1. 家庭账号卡作为主视觉。
2. 报告/设备/成员三个摘要块横向排列。
3. 设置入口分组，而不是连续列表。
4. AI 规则和隐私作为高优先级入口，不沉到普通设置列表。

## 6. 旧版布局废弃清单

以下在 v2 中明确废弃：

- 旧版绿色 accent 和绿色 tabbar。
- 网格背景、厚重手机壳、桌面控制台右栏。
- 所有页面都用同一种卡片列表堆叠。
- 首页状态卡三指标作为首屏主体。
- 任务页普通纵向任务列表作为主体。
- 实时看护功能按钮平铺面板。
- 告警详情普通详情卡片。
- 我的页设置列表堆叠。
- 大量边框包裹的后台式卡片。
- 使用旧版 `row`、`metric`、`card` 形态作为主组件。
- 旧版页面顺序一比一迁移。
- 为了覆盖状态牺牲视觉质量。

| 关键页面 | 旧版问题 | v2 改法 | 参考来源 | 设计目的 |
|---|---|---|---|---|
| 首页 | 状态卡、待处理卡、快捷入口堆叠，像控制台 | 主视觉看护卡 + 今日状态摘要 + 横向任务/事件卡 + AI 解释卡 | Travel Discover / Aspen 首页 / Miquido AI card | 让家长先看到“孩子现在的场景”，再理解状态 |
| 任务页 | 普通日期条 + 纵向任务列表，像任务管理后台 | 日期横条 + 今日主任务大卡 + 横向模板/小书包卡 + AI 建议 chips | Travel 分类 tab / Aspen 横向卡 | 把“今天最重要任务”前置，而不是平铺所有任务 |
| 实时看护 | 视频区域小，下面是功能面板和列表 | 视频/画面主视觉 + 浮动控制 + 圆角信息面板 + AI 状态解释 | Travel/Aspen 详情页大图头部 / Miquido 状态解释 | 让看护像真实摄像头 App，不像设备后台 |
| 告警详情 | 普通详情页，证据和规则权重不够 | 证据大图/视频头部 + 圆角信息面板 + 底部处理 CTA | Travel detail / Aspen detail | 告警先看证据，再处理，而不是读表格 |
| 我的页 | 设置列表堆叠，入口密集 | 家庭账号卡 + 报告/设备摘要 + 分组入口 | Aspen 卡片分区 / Miquido 轻统计 | 让账户中心更像家庭 App，而不是设置页 |
| Tabbar | 旧版绿色中央按钮和厚重底座 | 白色凹形浮动底座 + 蓝色中央创建 + open state 弧形快捷动作 | Navigation Bars UI Kit `12:1117` | 建立全新底部导航识别度 |
| AI 解释 | AI 只作为标签或普通说明 | AI disclosure + confidence capsule + why-this 短句 + 操作 chips | Miquido Chatbot / AI-native patterns | 让 AI 判断可解释、可接受/驳回 |
| CTA | 多按钮平均分布 | 每屏一个主 CTA，次操作变浮动图标或 chips | frontend-design rules / Travel detail CTA | 降低家长决策成本 |

## 8. v2 三屏实现边界

本轮只实现：

1. 首页 `home`
2. 任务首页 `tasks`
3. 实时看护 `watch`

不做全量页面迁移，不做完整状态矩阵迁移。三屏必须先证明视觉方向成立。

每屏最低状态：

- default：真实业务数据和可点击导航。
- lightweight feedback：tab 切换、创建展开、toast、AI chips。
- 不在本轮实现全量 `loading/empty/error` 页面，但组件结构预留状态层。

## 9. v2 Acceptance Notes

交付前必须自检：

- 三屏骨架必须明显不同于旧版。
- 不复用旧版 DOM/CSS/组件命名。
- 不出现后台控制台右侧页面清单。
- 不出现旧版绿色 accent。
- 不出现所有内容都被同一种卡片包裹。
- 移动端优先，桌面只是居中预览。
- 使用真实业务数据和真实图片。
- Tabbar 的凹形底座、中央按钮、展开快捷动作必须完成。
