## 自动日更尚未完成的三个环节

1. **内容被拒绝后，尚无通用自动纠错。** 当前英语第二份重复题已被正确拦下，但仍需定位和修复生成原因；能拒绝错误不等于能无人值守生成合格替代内容。
2. **音频失败或结果不明仍需人工按证据恢复。** `ambiguous` 等状态必须核对已派发调用、保存音频、ASR 和费用回执，再决定合法恢复路径；不能盲目重试、降低阈值或把结果不明当作成功。
3. **供给目前是缺下一课才补一组，尚无多课提前库存缓冲。** 当前缺口触发机制不能保证孩子连续学习时，后续多课已提前备好；同一课注册了两组槽位，也不等于两组都已生成、验收并入库。

因此当前仍是受监督的分批生产与交付，不能描述为全课程已备齐或自动日更已经无人值守。日常 worker 的启用和长期预算范围另行明确；本次 6 份授权不自动扩展为全目录持续生产。完成本批后也不能以启用 worker 代替上述库存与恢复能力的实际验收。

### 生成提示与策略的一致性：已定位，后续方案尚未实施

本批英语第二份的实际冻结输入采用 `mira.openmaic.playful-learning.v1`，`threeDUsage=teaching_need`；不是要求独立 3D 页的 v2。只读核对当前 Native session 的保存提示，仍有“语言课可用 2D、无强制 3D”的说明，没有 `EXPLICIT 3D AND GAME REQUIREMENTS v2`。该提示 SHA256 为 `c7d0e007419f741adfe4be84dae20d41cbdd6b67f9bd489c23ef07d8f8e3eb6f`，对应 job `omformal_90ed56f8cb07a09d6c51296a`。因此最初缺独立 3D 页不能归因为 v2 要求已经生效却被模型忽略。本次通过当前任务中的明确补全指导继续制作，不修改原冻结输入；是否最终满足要求仍以实际课堂和审核为准。

策略的实际传递链是：`OpenMaicFullRuntimeClient.selected_professional_creation_policy()` 在目标创建时读取 `MIRA_FORMAL_PLAYFUL_REQUIRE_3D=1` 才选择 v2 → `learning_curriculum_preparation_contract.py` 将策略冻结进 target → `openmaic_runtime_repository.py` 从 target 读取正式权限 → `openmaic_full_runtime_service.py` 写入 generation contract 和 formalInput → Native `professionalPrompt()` 调用 `withMiraFormalPlayfulInstructions()` → `requiredThreeDInstructions()` 仅在 `threeDUsage=required` 时追加独立 3D 与 game 要求。同一策略还传入单页 content/actions 提示和独立质量审核。模板中旧的“四题”措辞已由 progressive 投影替换为注册题目，并非当前六题任务的实际矛盾。

另一个已定位的提示缺口是：`EXPLORATION_PROMPT` 虽列出 `feedbackSelector`、`resultText`、`explanationText`，并要求 reset 恢复基线，但没有明确说明同一个可见反馈容器必须同时包含完整结果和解释，reset 必须恢复声明状态的模型、结果和解释，而不是清空为未作答。本次 p3 将结果与解释放在两个兄弟节点，实际点击成功后仍因严格 DOM 条件不满足而超时；reset 清空也与声明的已完成基线不一致。修订提示应解释现有验收规则，不降低规则或改变互动完成条件。

**后续最小方案尚未实现、尚未激活：** 对明确要求每课独立 3D 与游戏的新批次，在创建 target 前显式选择并核对必需 3D 策略；用新的冻结提示版本承载反馈容器、reset 的明确说明，并消除“语言课不要强制 3D／不固定 widget 组合”与该批必需页面的歧义，其余页面仍按教学需要选择。Native 完成与恢复路径会重新计算并严格比较 `professionalPrompt()` 与保存提示，直接修改共享常量可能使旧 session 身份校验失败。因此必须保留旧版本提示字节，不热改当前环境、本批 target 或在途输入，也不重新生成已正式发布的五份。本节记录的是后续工作边界，不是已完成的通用修复。
