# Mira Guardian 家长端 App 设计规范

本文基于 `README.md` 中的家长端 App 需求、`docs/ai_camera_parent_needs_product_tech_plan.md` 的产品技术方案，以及 [VoltAgent/awesome-design-md](https://github.com/VoltAgent/awesome-design-md) 的设计系统思路整理。参考方向以 Apple 为主：Apple Home 的设备控制、Apple Health 的日报和趋势、Apple Photos 的真实影像呈现、iOS Liquid Glass 的半透明层级与动态材质；同时参考 Google/Nest Home、米家、Airbnb、Intercom 在家庭设备、真实生活场景和温和状态表达上的成熟模式。

## 需求分析摘要

Mira Guardian 是 iOS 和 Android 双平台家长端 App，不是孩子端娱乐入口。它的核心任务是让家长快速知道孩子当前状态、今日流程完成度、待处理事项，并能完成设备绑定、孩子档案、一日流程、任务计划、任务证据、专注计时、实时看护、报告、积分奖励、打卡、安全告警、隐私和家庭成员管理。

首屏要服务三个高频问题：

- 孩子现在是什么状态。
- 今天的任务和一日流程完成得怎么样。
- 有没有需要家长立即处理的事情。

产品气质应是“可靠的家庭看护工具”，不是安防监控后台，也不是儿童娱乐 App。设计要温柔、清晰、可解释、有边界。新版 HTML 原型应覆盖完整可点击路径，而不是只展示少量静态样张。

## 页面覆盖范围

| 模块 | 必须设计的页面 | 关键点击效果 |
|---|---|---|
| 首次使用 | 欢迎页、登录页、设备扫码、Wi-Fi 配网、绑定成功、孩子档案、摄像头命名、紧急联系人 | 下一步推进、扫码反馈、绑定成功动效、资料保存反馈 |
| 首页 | 当前状态、今日流程、待处理事项、快捷入口、睡眠晨起卡片 | 快捷入口跳转、待办打开详情、底部导航切换 |
| 流程 | 今日流程、流程项详情、带书清单、睡前流程、临时调整 | 流程项编辑抽屉、完成/延后/跳过、添加临时物品 |
| 任务 | 今日任务、任务详情、任务证据、专注计时 | 证据确认/驳回、专注开始/暂停、AI 误判原因选择 |
| 看护 | 实时画面、云台控制、音频通话、截图、事件回放 | 查看前隐私提示、通话抽屉、截图 toast、视角切换 |
| 报告 | 日报、周报、成长时刻、睡眠趋势、学习求助摘要 | 摘要展开、证据回看、成长时刻收藏、删除或分享 |
| 积分奖励 | 积分总览、流水、奖励商店、兑换审批 | 兑换审批抽屉、手动补分、撤销自动加分 |
| 打卡 | 打卡任务、素材审核、历史素材 | 审核通过/驳回、保存或分享素材 |
| 安全 | 安全事件、事件详情、安全区域、紧急联系人 | 一键通话、指派处理人、标记误报/已解决、安全区域新增/校准 |
| 设置 | 孩子档案、设备管理、家庭成员、人设与语音、隐私与权限、通知设置、帮助反馈、关于我们、版本更新 | 开关状态、权限说明弹层、成员角色切换、反馈提交、检查更新 |
| 内容生态 | 课程表导入、合作内容入口、学习缺漏诊断预留 | 导入课程表、展示合作内容状态、明确第三方自动提交边界 |

## 设计原则

| 规范 | 适用场景 | 不要怎么用 |
|---|---|---|
| 1. 首屏信息只放三层：当前状态、今日进度、待处理事项 | 首页、通知落地页、App 冷启动后的默认页面 | 不要把报告、积分、设置、安全、任务全部平铺在首页，避免家长打开后不知道先看哪里 |
| 2. 状态表达先给结论，再给证据 | 孩子状态卡、任务证据、报告摘要、安全事件详情 | 不要只展示原始时间线、置信度和截图，让家长自己推理发生了什么 |
| 3. 颜色使用“信任蓝 + 守护绿 + 温暖珊瑚 + 风险红” | 蓝色用于实时看护和主操作，绿色用于正常/完成，珊瑚用于家庭温度和奖励，红色只用于紧急/风险 | 不要把红色用于普通提醒、扣分或未完成任务，也不要让整套界面只有一个蓝色调 |
| 4. 大面积背景保持安静，关键模块再用颜色 | 首页、流程、报告、设置等需要长时间阅读的页面 | 不要用满屏高饱和渐变、发光背景或复杂纹理，会削弱家长对数据的信任 |
| 5. 图片必须服务真实家庭场景 | 实时看护入口、成长时刻、打卡审核、任务证据、报告精选片段 | 不要使用抽象插画或灰色占位图替代孩子学习、房间、书桌、证据截图等核心内容 |
| 6. 影像上叠加信息要克制 | 实时画面、事件回放、成长时刻封面 | 不要在图片上堆多层按钮、长文本和大面积遮罩，尤其不能挡住孩子动作和环境证据 |
| 7. 卡片圆角控制在 8px，强调秩序感 | 首页状态卡、流程项、任务证据、报告模块、设置列表 | 不要使用过大圆角、胶囊堆叠和卡片套卡片，让工具界面变成营销海报 |
| 8. 触控目标不小于 44px | 底部导航、快捷操作、确认/驳回、通话、截图、云台控制 | 不要把多个小图标挤在同一行，尤其是安全事件和实时看护里的误触成本较高 |
| 9. 导航以家长工作流分组 | 首页、流程、看护、报告、设置等一级入口 | 不要按照后端模型或功能清单机械拆 tab，例如把任务证据、专注计时、流程模板全部放成一级入口 |
| 10. 任务和流程用时间线表达连续性 | 一日流程、睡前流程、带书清单、任务执行记录 | 不要用孤立卡片列表呈现流程，否则家长难以判断前后依赖和卡在哪里 |
| 11. 证据模块必须给出操作闭环 | 任务证据、打卡素材、安全事件、AI 误判纠正 | 不要只让家长“查看”，必须提供确认、驳回、改判、标记误判原因等动作 |
| 12. 实时看护要同时显示隐私状态 | 看护页、实时画面入口、音频通话、截图、事件回放 | 不要把实时画面入口做成普通视频 App，也不要隐藏设备端提示、隐私模式和记录策略 |
| 13. 安全事件视觉层级高于普通任务 | SOS、陌生人/敲门、危险区域、异常声音、紧急联系人 | 不要让安全事件和普通“作业未完成”使用同样的样式和优先级 |
| 14. 报告避免焦虑化措辞 | 日报、周报、学习求助、睡眠趋势、行为趋势 | 不要使用“失败、糟糕、落后、扣分严重”等评价词，建议用事实和下一步建议 |
| 15. 积分以正向激励为主 | 积分总览、奖励商店、兑换审批、积分流水 | 不要默认开启自动扣分，也不要让积分页面像惩罚榜单 |
| 16. 对话和人设设置强调边界 | 唤醒名、孩子称呼、声线、聊天时长、记录策略 | 不要把 AI 伙伴包装成无限陪聊对象，也不要默认展示逐字对话记录 |
| 17. 空状态要给下一步行动 | 新家庭、未绑定设备、没有任务、没有报告、隐私模式开启 | 不要写“暂无数据”就结束，应告诉家长下一步可以绑定、创建、开启或等待生成 |
| 18. iOS 和 Android 保持同一信息架构，遵循平台控件习惯 | 双端 Flutter 实现、底部导航、权限弹窗、系统分享、推送设置 | 不要在两端做两套不同的产品逻辑；也不要把 iOS 风格的毛玻璃和 Android Material 控件生硬混用 |
| 19. 所有权限和数据保存动作要前置说明 | 远程查看、录像、截图、语音记录、儿童数据导出和删除 | 不要在用户触发后才解释为什么需要权限，也不要把儿童隐私设置藏在多级菜单底部 |
| 20. 动效只用于状态变化和空间切换 | 任务完成、告警确认、流程推进、底部导航切换、报告展开 | 不要做持续漂浮、背景光斑或装饰性大动效；守护类产品需要安定感 |
| 21. Liquid Glass 要服务层级，不做装饰 | 顶部栏、底部导航、抽屉、浮动快捷操作、实时画面上的状态条 | 不要让所有卡片都透明，否则文字可读性和信息分组会变差 |
| 22. 玻璃层后面必须有可辨识的真实内容 | 实时画面、成长时刻、设备绑定成功页、家庭首页背景 | 不要在空白背景上强行叠玻璃，液态玻璃需要环境色和光影支撑 |
| 23. 重要文本必须落在实底或高对比玻璃层上 | 安全告警、隐私提示、任务确认、报告结论 | 不要把低对比灰字直接放在半透明图片上 |
| 24. 交互反馈要像 iOS：轻、快、明确 | 按钮点击、页面切换、确认成功、底部抽屉弹出 | 不要使用夸张弹跳、复杂粒子或长时间 loading |
| 25. 原型必须可点击验证路径 | 首次使用、任务证据、实时看护、安全事件、奖励审批 | 不要只给静态页面截图，核心路径至少要能点击到下一步、返回和打开抽屉 |
| 26. 外部舞台背景不用真实照片 | 原型展示页、设计评审页、Figma/HTML 高保真舞台 | 不要用家庭照片做整体背景，会抢走 App 本身的层级；真实照片只放在看护、证据、成长时刻等业务内容里 |
| 27. 运营类设置页也要设计 | 关于我们、版本更新、帮助反馈、通知设置、学习内容入口 | 不要只做核心业务页，正式 App 还需要信任、售后、更新和内容生态入口 |

## 字体与排版

- iOS 使用系统 San Francisco，Android 使用 Roboto；Web 原型使用 `Inter` 和系统字体模拟。
- 页面标题建议 28-34px；卡片标题 15-18px；正文不低于 14px；移动端正文不低于 16px。
- 数字指标可用更重字重，但不要使用夸张大屏数据风。
- 中文文案保持短句，尤其是孩子状态、待处理事项、安全告警和报告建议。

## 组件规范

| 组件 | 适用场景 | 不要怎么用 |
|---|---|---|
| 状态胶囊 | 在线、隐私模式、学习中、睡前流程、待确认 | 不要把长句塞进胶囊，胶囊只表达状态，不承载解释 |
| 底部导航 | 首页、流程、看护、报告、设置 | 不要超过 5 个主入口，也不要使用不易理解的抽象图标 |
| 快捷操作按钮 | 实时看护、通话、截图、提醒、确认 | 不要只用文字按钮；能用通用图标的地方优先图标加短文本 |
| 时间线流程项 | 一日流程、任务、睡前、带书清单 | 不要把已完成、进行中、卡住、跳过都做成同一种样式 |
| 证据缩略图 | 作业、家务、打卡、睡眠、事件回放 | 不要裁切掉动作主体；需要保留足够上下文 |
| 报告摘要卡 | 日报、周报、学习求助、睡眠趋势 | 不要先展示复杂图表，结论和建议要在图表前面 |
| 安全事件卡 | SOS、陌生人、危险区域、异常声音 | 不要弱化处理按钮；必须有联系、查看证据、标记处理结果 |
| 隐私提示条 | 实时画面、录音、录像、逐字记录 | 不要做成可忽略的小字；需要清楚说明当前数据策略 |

## HTML 原型范围

新版高保真原型不再只做 4 个核心屏幕，而是以“完整可点击 App 流程”为目标。原型文件为：

- `design/mira_guardian_high_fidelity_ui.html`

它应覆盖 README 中的主要 MVP 模块，并能通过点击演示关键步骤。后续 Flutter 工程初始化时，可直接映射到 `onboarding`、`home`、`daily_flow`、`tasks`、`task_evidence`、`focus`、`watch`、`reports`、`points`、`rewards`、`checkin`、`conversation`、`emergency`、`privacy`、`settings` 等 feature。
