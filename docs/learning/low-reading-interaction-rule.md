# 一、二年级图像优先交互规则

用户在 2026-09-29 明确要求：一、二年级默认不能独立读懂文字，大多数游戏、课件、问题和答案都要用多图表达。这是跨学科、跨生成课件与手写课堂组件的产品约束。

- 题目先给与情境对应的大图，老师用短句读题；选项用可辨认的图片。人物选项展示固定造型，场景中明确谁在说、谁在听、谈到谁，不能让孩子先读姓名。
- 点图、拖拽、配对、示范模仿只是低阅读输入示例，不是玩法白名单；一屏一个任务。按钮有明确图形与至少 48px 的**可命中区域**，可通过透明命中层、内边距或伪元素扩大，不能把它误做成所有可视按钮都至少 48px 高的大胶囊。提供可重播语音和音频失败后的重试。
- 文字用于辅助与识字目标本身；允许放大目标汉字，但不能用满屏字卡代替情境，也不能把文字选项配上装饰图就算完成适龄设计。
- 低阅读保护的是非目标操作指令，不能删掉本课被教的汉字、拼音和阅读任务。目标字/拼音可准确放大，让孩子尝试辨认、拼读或借拼音阅读；测目标拼读时不要先把答案词读出来。被测拼音应和口播操作题干分离，请求帮助后才示范目标读音，并将获助结果与独立尝试分记。听词找图与拼音—图义匹配分开记录，规范发音与实际朗读仍须真实口语或明确的成人观察证据。
- 读题与反馈复用项目老师的预生成语音，不使用浏览器或系统机械音作为替代。
- 提示逐级增加，演示只在请求帮助后出现。作答前所有选项待遇一致，不通过颜色、位置标记或图片高亮泄露答案。
- 图片支持的理解任务不等于独立识字测验；学习记录必须明确能力证据的范围。

验收时遮住非目标文字：孩子听题后是否能找到情境、区分图片选项、选择、理解反馈并继续？再核对人物造型一致性、语音内容与图片一致性、小屏布局和恢复进度。

落实位置：根目录及 Student Web、OpenMAIC 的 AGENTS；`backend/content/low_reading_policy.v1.json`；`textbook_pedagogy.py` 的一、二年级教学约束。已有发布课程仍需逐课审核，更新规则不代表历史课件已全部改造。

## 所有教材课件的官方资源前置核对

用户在 2026-10-26 明确要求：此后每个课件制作前，必须先参考国家中小学智慧教育平台对应教材版本、年级、上下册、科目和课次的内容，包括视频、课件、教学设计、学习任务单和课后练习，再作有我们特点的原创改编。本节适用于各科、各年级的新课件；不是仅针对低年级或语文。

1. **先匹配身份与范围。** 核对官方教材名称、版本/出版社、出版信息、年级、科目、上下册、课次及所制作的课时，并和现有教材绑定对应。官方教材PDF与同步课堂的资源ID可以不同，必须用实际教材信息核对，不能只比较ID或同名课题。按具体目标组织学习段，官方课时数不是固定页数或课堂类型配额。
2. **逐类看实际内容。** 每个拟制作课时逐项审阅视频、课件、教学设计、学习任务单、课后练习，记录来源、实读页码或观看时段、目标、重点难点、示范方法、任务与检测意图。发音、笔顺范写、实验等要实际核对相关示范；打开链接、看到标题、列出目录或下载文件不算看过。视频标为已审阅时，画面和原音轨必须分别留下审阅者、带时区时间、实际输出方式、连续时段和具体发现；字幕、ASR或文字稿只能辅助核对，不能把连续画面或字幕阅读冒充实际听到原音轨。只有官方公开媒体元数据明确音频流为0时才能把音轨记为不适用；DRM、401/403、登录受阻或工具没有音频输出都属于未完成，不能伪装成无音轨。未读、未看完或访问受阻必须保留未完成状态，除下述用户明确限定的不可取得媒体例外外，不继续新制作；即使获得例外，也不能据此宣称已核对没有实际看到的动态笔顺或发音。
3. **缺项如实记录。** 官方明确没有某类资源时，记录已核的官方资源列表位置和缺项情况；不能把登录要求、加载失败、404或自己没找到标为“官方未提供”，更不能虚构已审阅记录。
4. **目标对齐，表达原创。** 从官方资源确定本课要教什么、学到什么程度及重点难点，再设计我们自己的连续人物/场景、有效图片、教师预录音、学科相关决策、可见结果、具体反馈、修改和迁移。不得原样搬运官方视频/PPT、原题、台词、插图或版式；也不能只换皮或加小游戏，却漏教偏旁、拼读、规范书写、朗读等目标。官方采用的儿歌、海报或某种练习是可参考的方法，不自动变成必须照搬的模板。
5. **把核对结果交给实际生成。** 新教学稿在 `scopeReview.officialResourceReview` 记录精确绑定、各课时五类资源状态和发现、需要保留的目标、原创改编方案及证据边界。v4 工作台在本地冻结完整统一政策与逐页合同，再派发由它们生成且带来源摘要的 compact 作者合同；完整审查材料不重复塞进作者提示。工作台准备/派发校验能阻断缺项与明显错配，不能自动证明作者实际看完或语义已符合，仍须审核内容与实玩。其他历史入口不因规则文字更新就自动获得该结构校验；新教材制作不得绕到尚未接入的入口跳过前置核对。
6. **保留历史身份。** 旧冻结请求、图片、付费回执和已保存成果保持不变。已派发会话仍按原身份查询/恢复；缺少前置核对的未派发旧稿不能直接新开付费制作，须保留原件并形成可追溯修订。不能向历史快照补一个“已看”字段后宣称此前已执行新要求。

只有用户针对某一课、某一修订明确授权时，才可对确实无法取得的 `video` / `courseware` 逐项记录 `waived_unavailable`；教学设计、学习任务单、课后练习仍必须实际审阅，官方对应课时资源清单经实际核对确认确无时才按严格来源缺项规则记录 `not_provided`，不得将它们一并豁免或伪造内容审阅。每项例外在该课自己的 `scopeReview.officialResourceReview.reviewExceptions` 保存 `resourceType`、准确 `binding`、`classHourIds`、`authorizedBy=user`、带时区 `authorizedAt`、用户原话 `userInstruction` 及 `reason`，并保留资源查找位置和无法取得的说明。不能伪标 `reviewed` 或 `not_provided`，不能写入公共策略充当长期授权，也不能自动沿用到另一课、另一册或后继修订。课程专属授权、教材发现和复核结论只保存在该课可追溯的 `scopeReview` / frozen 数据中。

## 课后练习、周末测评与家长报告

用户在 2026-10-26 要求：每课依据智慧教育平台对应的课后练习保存教学目标和题源，供周末约30分钟AI原创测评/复习使用，家长报告据此判断，并将可归档资源上传MinIO。

- 在现有教学稿 `scopeReview.postClassPractice` 保存官方课时/位置、具体练习目标、评分或观察依据、原创变式范围及证据边界。完整题源可以作为附件，以原字节SHA冻结引用。自有审阅记录与官方下载文件分清；未下载文件不能编造其SHA。实际课时数、题源数量、资源发现及复核结论只写入对应课程记录，不固化到这份公共规则。
- 每项进入课件的课后练习映射写入 `scopeReview.postClassPractice.inCoursePractice`，记录 `activityId`、`goalId`、`classHourId`、`page`、`sourceLocations`、`originalDesign` 和 `evidenceClaim`。适合屏幕互动且属于已教范围的目标，应成为原创练习或迁移活动；不照抄官方题干、选项、图片或版式。纸笔书写、真实口语或需成人观察的目标可以留给周末/线下，但课程记录必须说明为什么不纳入屏幕判断及其证据边界。
- 后台使用现有配置的AI生成变式，独立核题，准备有意义图片与教师预录音，再由明确身份的审查者审核。审核记录必须诚实区分AI/维护者/用户与没有取得的人工听验。题包通过MinIO上传、全量读回和registry登记后进入现有复习池；学生GET不调用付费生成，也不在持锁事务里等待AI。
- 沿用 `tasks`、周末复习和逐题作答证据。目标约1800秒，可以分段暂停，按实际已学教材版本/发布身份/目标和题目估时选取；不能把仅打开课件当作全部学会。题量不足显示范围和时长缺口，不反复同题凑30分钟。旧卷的冻结政策、题目和作答保持原样。
- 家长报告依据题目的 `targetId`、`assessmentMode`、`evidenceClaim` 和真实首答、提示、复现与修改来表达具体表现。图片点选、拼音—图义匹配不自动证明规范发音、朗读、背诵或纸笔书写；没有相应证据就保留待观察。未参加、未知成人帮助和练习自报不能变成能力失败或独立掌握。
- 自有题源、课件、图片、语音、题包、候选和发布资料走现有MinIO归档及精确字节校验，随后用registry读回；本地文件存在或上传请求返回不算完整交付。owner cookies、API密钥等鉴权材料保持私密，家庭作答和报告继续由受鉴权数据库管理。

## 游戏玩法与操作方式

用户在 2026-10-19 明确要求：课程游戏应具备 OpenMAIC 官方 Demo 展示的玩法多样性，不能只做拖拽或换图点选。上述点图、拖拽、配对是低阅读的操作方式，不是游戏类型清单；操作可靠也不代表游戏有趣或多样。

用户随后提供的[官方 Demo 课程](https://open.maic.chat/classroom/stage-PqxzPNyWJZ8G)展示了参数调节后观察发音部位变化、声调爬阶、移动收集拼音部件等自由 HTML 机制。这里只参考“直接操控—状态变化—结果反馈”的设计方法，不复制其教学文字、题目、画面或错误内容；我们的教材准确性仍以已核课程资源和独立审查为准。

- 每个游戏的教学稿必须说明任务目标、孩子可作的决策、状态如何变化、结果如何验证，以及失败后能尝试什么。按这些实际机制审核多样性；改 `widgetType`、背景、字卡、分数或动画不算一种新玩法。
- 结合教材选择探索收集、构建与试验、调整条件观察结果、空间路线任务、听音记忆、角色轮流合作、情景分支等机制。相邻活动若重复同一机制，说明巩固同一技能的教学理由；不能连续用同模板换皮充当新游戏。三选一可用于测评，但不能覆盖整节课的主要活动。
- 参考官方 Demo 的决策与反馈设计，再按本课知识和年龄改编；不为了凑类型加入无关的 3D、编程、计时或敏捷操作。数、字形、发音等需精确的内容仍使用已核素材和教师语音，不能用随机游戏效果代替准确性。
- 逐页实际操作验收必须记录“孩子做了什么、改变了什么、从结果学到什么”，同时检查与前后页的机制是否相同。图片支持、预录语音、适龄、玩法多样性分别验收；不能用页面类型数量或拖拽测试通过代替。
- 自由 HTML 游戏可按目标使用 DOM、SVG、Canvas、声音、动画与状态机。可玩场景、知识对象、路线、结构、参数或作品应占主要舞台；开始、帮助、重播、重置和确认等控件保持辅助地位。普通辅助按钮的可视芯通常约 28–40px，通过更大的透明命中区满足触控，而不是铺满全宽药丸或等大按钮矩阵。
- 需要官网式连续闯关体验时，采用“图像/教师语音开始层 → 当前关卡任务 → 具体反馈 → 无惩罚重试或修订 → 下一关 → 总结”的游戏壳。开始层只保留一个主开始动作；HUD 可显示紧凑的关卡、进度、课堂分数或收集物，但不得遮挡主舞台，分数不作为学习证据、家长判断或正式积分。刷新恢复当前关卡，重播语音不重置作答。
- 关卡数量由本课教材目标决定，不设固定配额。相邻关卡要增加新的知识决策、条件、情境或迁移，而不是同题换图；一年级遮住非目标文字仍应能从情境图、动作示意和教师预录音知道如何开始、操作、理解反馈并继续。
- 把画面做成白卡/题卡墙、用一组大按钮替代场景、点击按钮只换文案/分数、或让拖到唯一答案成为整课主要体验，均属于失败。验收除有效/错误/修订/恢复路径外，还要看舞台占比、按钮与卡片占比、控件层级和误触；“HTML能打开、按钮能点”不代表质感或玩法通过。

官方参考入口：[OpenMAIC 官方仓库](https://github.com/THU-MAIC/OpenMAIC) 与其链接的 [Live Demo](https://open.maic.chat/)。新稿采用本要求；已冻结、正在生成或已发布课程仍保留原成果，按具体课次另行评审，不因规则更新自动重生成。

## 课件本体质量与完整体验

用户在 2026-10-21 进一步明确：验收不能只看手机尺寸、按钮能否点击、音频能否播放，或代码中是否存在 `domainState`。要先判断孩子实际经历的是不是一节完整、有吸引力、与教材目标一致的课。

- 整课先有清楚的儿童任务和学习主线。情境、示范、尝试、反馈、修订、迁移和回顾应形成推进；窄目标可以短，但不能由互不相干的幻灯片、题卡和控件拼成。
- 人物身份、造型、动作、场景关系和美术语言保持一致。主要画面要承载谁在做什么、为什么操作和结果怎样变化；通用头像、装饰插图、文字条、卡片墙和大片空画布不能代替课件内容。
- 真实机制必须在儿童可见的世界里成立。孩子操作后，知识对象、位置、数量、结构、路线、条件、角色说听关系、环境或作品要发生可理解的变化。隐藏 JSON、history、数据库记录或代码分支只能证明实现存在，不能证明游戏好玩或规则已经落实。
- 前页获得的人物身份、对象、关系、作品或证据应在后页继续发挥作用；同一人物不能在照片、通用插画和固定头像之间变脸。英语课尤其要让谁在说、谁在听、在问谁和回应谁直接可见。
- 不允许用非目标捷径完成主要任务。英语不能只靠同头像配对、姓名文字或固定位置，数学不能只靠颜色，科学不能只靠装饰性差异。若不使用目标知识也能稳定过关，相应学习证据和游戏设计均判失败。
- 不同错误原因要呈现对应的可见断点，并由教师语音指出具体对象或关系及下一步怎么改；多个 reason 共用一句泛化提示、只变徽章或只写日志不合格。
- 听音选卡、排序句子、连线和拖到唯一答案可作局部练习或测评，不能成为整课的主要体验后再用动画、得分、emoji、头像或语音按钮包装成多样游戏。核心活动应形成角色任务、情境探索、构建试验、条件比较、记忆策略、合作轮流或可编辑作品，并有清楚的后果和修改空间。
- 发布前按完整课序做课件本体审查，每个核心活动保存 before、action、after、revise 四个真实状态，分别判断教材主线、儿童任务、统一美术与角色、可见世界变化、目标不可绕过、机制差异、反馈修订和迁移。静态检查、移动端可点、正式配音、页面数量和单页截图均不能替代这个结论；任一硬失败都不能由其他分数抵消。

这些要求写入同一份 `textbook_interaction_policy.v1.json`，由 `CLAUDE.md` 继续直接导入。规则升级只影响新冻结任务；已冻结或已发布课程必须保留原版本并通过可追溯修订重做，不能修改旧快照后宣称历史课程已符合。

## 统一生成规则与官方 Demo 对照

四科共用的完整规则为 [`textbook_interaction_policy.v1.json`](../../backend/content/textbook_interaction_policy.v1.json)。新 v4 工作台任务在 `prepare` 时把完整规则快照、完整逐页合同及其摘要保存在本地冻结记录，并从中生成带来源摘要的 compact 作者合同。派发只发送一份 compact 作者合同和原始已审请求，避免完整政策、官方审阅记录和逐页合同重复占用创作上下文。再次准备、查询、恢复、附件派发和派发前修订沿用同一冻结身份；不能从当天规则重新投影或改变请求身份。

新版工作台冻结格式 `mira.operator.workbench-authoring.v4` 保存完整 `interactionPolicy`、`sceneContract` 和派发用 `authorDispatchContract`。完整 `sceneContract` 仍含教材绑定、目录及课次摘要、教师、`scopeReview`、逐页 `pagePlan`、`qualityRules` 与 `lockedAssessments`，供本地完整性校验、保存审查和追溯；`authorDispatchContract` 只投影作者完成课程所需的范围、目标、页面权威、锁题、资源摘要与精炼创作规则，并绑定来源 `sceneContract` 摘要。低年级测评图片、题干配音、答案不提前泄露等权威边界继续保留，精简不代表放松验收。

与之配套的原生编号补丁让内容及动作生成器读取 v4 compact 作者合同，并在候选中保留其身份；保存阶段再用本地完整冻结合同核验页面、锁题、教材来源及策略摘要。实际图片生成后才绑定原字节、尺寸和摘要，实际语音文本生成后才核验本页 cue 与 speech。保存的候选台账须与真实工作台任务、教材目录和课堂内容一致；缺失或变化不能退回普通课堂路径绕过检查。首次候选素材替换保留历史，已保存页面引用的素材须通过后继修订变更。这个机制不能自动判断图片语义、操作是否有教学价值或儿童已掌握，仍需遮字检查、实玩及真实录音验收。派发新 v4 任务前须确认对应原生补丁已加载。

v4 工作台由 compact 作者合同明确覆盖 `mira-primary-courseware`、`deep-interactive` 中冲突的通用默认，同时把完整政策和审阅证据留在本地冻结记录供守卫与验收使用。原生技能目录只保存绑定公共策略版本与摘要的作者体验投影，供通用创作指引使用；它不是第二套可独立演进的完整规则，实际课程仍以冻结 dispatch 的 `policyRef`、`authoringRules` 和本地完整合同为准。结构约束调整通过编号补丁持久化。历史 v1、v2、v3 任务及旧版 formal 包装器保持各自原始请求、技能正文、逐页上下文与摘要，不补写 v4 合同、不重新派发，也不宣称自动升级。原生技能正文和约束存在不同缓存/读取方式，因此有活跃生成任务时不得修改运行目录或重启来宣称只升级新课；新工作台请求先接入，原生补丁在队列安全空闲时再应用。

本次对照的是官方课件中可观察的交互，不是将其整课难度或视觉细节照搬给低年级：

旧质量提案已经包含真实状态、错误恢复、解释反馈和迁移等要求；主要差距是规则分散、类型轮换等要求互相冲突，且该提案未接入当前工作台。此次把这些已有要求与新的机制合同、证据边界一起纳入实际新任务请求。

| 官方样例及机制 | 我们原规则的差距 | 新规则 |
| --- | --- | --- |
| [分数](https://open.maic.chat/classroom/U96_9bhRtme4owN8NK3Cs)：分切、交付、分数搭桥、改变切线判断等分 | 用不同 `widgetType` 包装相同听音选卡，难以产生不同学习过程 | 用决策、领域状态、状态变化、结果和学习证据比较玩法；同类型允许不同机制，不同标签不保证多样 |
| [电路](https://open.maic.chat/classroom/mWaTO92icaXwC4eZgv1Jb)：搭线路、调整信号 | 只选答案后播放成功动画，缺少可探索模型 | 由儿童操作改变真实状态，结果按结构/条件计算；保留中间结果，可修改后再试 |
| [Photoshop](https://open.maic.chat/classroom/adSd7bead8SsLX2FNjWng)：短讲解穿插实验、自由涂抹蒙版 | 正文强制全互动、每次都唯一正确点击 | 允许必要讲解与观察；适合的目标提供多条有效路径和可修改的作品，不给开放表达伪造唯一答案 |

这些例子不要求一年级学分数、电路或编程。每科按精确教材目标改编，不能为了凑玩法加入新知识。数学可用一一对应和轮廓试装，语文可用声音比较、字形轨迹和情景表达，英语可用轮流沟通与语义分支，科学可用观察、比较和证据记录；每课选择需要的组合。

### 计划与验收共同使用的规则

1. 每个主要活动记录真实教学角色、教材目标、儿童决策、领域状态、状态变化、可观察结果、修订机会、输入方式、渲染类型和证据边界。重复机制须说明具体巩固理由与迁移安排；理由本身不自动代表通过。
2. 不再要求正文全互动、互动占比至少 60%、相邻页更换类型、固定页数或最低游戏种数。页面按情境、示范、尝试、解释、巩固和迁移的需要组织。一屏一事允许同任务通过多阶段推进。
3. 游戏需有可理解的目标、规则、知识相关决策和由操作产生的后果。观察、描写、配对等可以诚实称为活动，不必全部叫游戏。全课同一选择模板换皮不能算达到多样性要求。
4. 结果须由真实对象、几何、条件、路径或作品状态计算；错误说明可观察原因，并允许改条件、撤销或重试。低年级提供宽容触控和等价易操作路径，不把手部精度或速度当成学科能力。
5. 图像理解、教师预录音、玩法、移动端操作、恢复、学习证据分别验收。播放器、音频门控和指针可靠性不能计入玩法数量。不得把点击/听过/看过/同图配对推断为认字、发音、口语或现实行为已掌握。
6. 3D、视频、编程须有具体教学收益；不要求每课/单元强制配置。旧 `textbook_courseware_quality.v1.json` 标记为 `proposed_not_enforced` 的配额不作为新工作台默认要求；其文件、旧冻结合同和现有发布校验不被改写。来源、正式音频、独立审查及发布权限等非冲突边界继续保留。

验收要实玩有效路径、错误/替代路径、修改/重试和进度恢复，并对照代码验证机制。开放表达要验证多种作品可保留修改。报告分开列出：规则已附、草稿生成、实玩、音频、审查、发布回执、学生入口。**目前的自动接入证明规则已交给生成器，不是自动判定语义质量，也不代表历史语文课已经变得多样。**
