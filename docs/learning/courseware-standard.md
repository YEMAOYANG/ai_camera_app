# 课件制作标准（唯一标准）

适用于所有新做的课件（各科、各年级）。它取代 `low-reading-interaction-rule.md`、`backend/content/textbook_interaction_policy.v1.json`、`backend/content/textbook_courseware_quality.v1.json` 和 `backend/content/low_reading_policy.v1.json`。已发布的旧课保持原样；这些旧文件只在旧课还需要校验时保留，不得用于新课件，旧课退出时一起删除。

## 一、做课前

1. **读官方资料。** 国家中小学智慧教育平台对应教材版本、年级、册次、课次的教学设计、课件、学习任务单、课后练习（视频可豁免，用户 2026-10-30 已批准）。只取"教什么、教到什么程度、练什么"；画面、台词、题目一律原创，不搬原文。
   **同一教材课目有多个官方课时时，先审读全部课时资料，整合成一个完整课件，不把官方课时拆成多个上架课件。** 已上架但只覆盖部分课时的课件，应补齐为完整新版并替换同课旧版；旧版和发布证据保留作回退。（用户 2026-11-05 明确）
   **外研社一年级英语**须先读外语教学与研究出版社对应版本、起点和册次的原教材。记录完整课目页码及配套课时，结合智慧教育平台对应资料核对。教材页和平台课目名不一致时，先核对版本、模块、单元及完整内容边界，再写笔记。
2. **写 `official-notes.json`。** 每类资料的目标、重难点、课后练习，带页码引用。没有笔记不开工（闸门 G0）。
3. **写简要稿 `brief.json`。** 目标 / 页序 / 每页玩法 / 小检查题 / 课后练习去向。页数按目标定，不凑数。
   **官方未提供配套资料时**：对准确教材的官方完整资源清单留存 URL、内容哈希和精确课目检索证据；未提供的类别如实记为 `not_provided`，不能写成“已审读”。若该课全部配套资料都未提供，须先取得并逐页审读准确版本的完整官方教材课目（含页码边界、书目/版本证据），另列教材审读记录；学习目标明确标为依据教材整理的原创教学目标，不能冒称官方教案目标。此时可按完整教材正文原创，G0–G8 不减免，G7 必须逐句逐题对照教材。只有目录标题、资源请求失败或未读全课正文时仍不得开工；403 不能当作未提供资料的证据，不得以其他课或其他版本顶替。
   **正文由负责该课的 agent 直接写成成品，不再经过 OpenMAIC 自动生成（不调用 DeepSeek）。** 负责该课的 agent（Codex 或 Claude）审读全部课时资料、写好官方笔记和简要稿后，直接写出讲解台词、互动页和小检查（`lesson.json` 与互动页源码），用公共框架构建；OpenMAIC 只负责保存和给孩子播放。记录教材节点、源文件哈希、作者模型和可编辑源码，后续修订保留修改证据。已冻结但尚未生成的 OpenMAIC 输入，直接作为该课简要稿的参考由 agent 写成品；已有的生成任务、初稿和已发布课件的证据保持原样。（2026-11-05 曾改为 OpenMAIC 调用 DeepSeek 写初稿；实测 18 门已上架课的初稿台词几乎全被重写，余额耗尽还让多门课停工。用户 2026-11-08 确认取消这一步。）

## 二、页面

4. **讲解页**：画布 1000×562.5，文字框互不重叠、不出画布，一页一件事。
5. **互动页**：逻辑画布固定 1280×720、铺满，统一用公共框架 `courseware/kit`：开始页（本课插图 + 一个开始按钮）→ 关卡点 → 星星 → 音效 → 逐级提示 → 第一次答错不报正确答案 → 完成页；图片加载失败有后备；按钮可点区域 ≥44px。
6. **不放“课堂讨论”指令（discussion）**：它现场调用付费模型（本机付费课堂互动是关着的），学生端也只接待自己名单里的同学，一二年级孩子更无法输入。想请孩子思考的问题，写成同学提问的老师台词，如“小满问：……说给大人听”，用老师预录音读出（G3）。
7. **老师真正讲课**：每个学习目标都要在老师的话里讲清楚：用孩子听得懂的话解释概念，给一个具体例子并说出每一步为什么，说出规则或要点；只会说“看这里、点一点”、念图上的字，不算讲解。讲解页至少 6 句、100 字，互动页至少 5 句、90 字（《整理和复习》平均 160 / 130 字，一般 8–10 句）。每个互动页老师至少 3 次操作画面（高亮 / 批注 / 揭示 / 设状态），目标元素必须真实存在，示范时边操作边讲为什么，再交给孩子做。老师每句话尽量 ≤25 字，讲解句和儿歌最长不超过 40 字（26–40 字只警告，超过 40 字不能上架）。猫头鹰、小满、朵朵可以用自己的声音提问、提醒、总结（句首必须报出名字，因为没有头像会亮起），不替老师讲必须讲的话，不抢答小检查。最后一页回顾本课的知识点。画面操作在先、讲话在后：讲解页的聚光灯 / 激光笔放在讲到该处的第一句话之前，要点、条目、步骤逐个依次点亮，一个不漏；台词里不放拼音字母（配音读不准），语文讲字音时说“江，第一声”，拼音留在画面上。
8. **互动页做成真正的小游戏，玩法由本课目标决定**，不套模板（用户 2026-11-08 明确：要像平常真正玩的 HTML 小游戏，不要千篇一律地点一点、拖一拖、按一按）：
   - 孩子实时操控画面里的角色或物体：跑跳、瞄准、投掷、抓取、接住、躲避、沿路驾驶等，讲究时机、速度和准头，操作结果马上在画面里看得见。
   - 本课知识是通关的关键：不会就过不了关，会了才能过；不能在一道选择题外面套一层游戏皮。
   - 每个游戏 2–3 关、逐关变难，有生命或重来；失误给提示、不惩罚，第一次失误不直接报答案。
   - 同一课里的游戏玩法互不相同。只靠点选答案、拖进格子、按按钮的页面不算小游戏，只在知识本身就是对应、摆放时才用，并在简要稿里写明理由。
   - 实时小游戏统一用公共游戏引擎 `courseware/kit/game.py`（页面脚本调用 `K.game`），引擎负责关卡、生命、重来卡、星星、音效和完成页。老师示范时用 `setState {demo:true}` 让角色自己玩（只循环当前一关），讲完用 `{demo:false, level:1}` 交给孩子；画布上的关键位置放跟随的锚点元素，老师的高亮、批注才有真实目标。
   - 一二年级的图片、读题、提示规则（第 9 条）同样适用。
9. **一二年级不靠认字就能玩，图片必须真的传意**：情境图、图片选项、老师读题；被教的字和拼音可以放大让孩子认；emoji、临时手画图标和抽象占位图不能代替有意义的教学图片。字词不能为了凑玩法硬配无关图或谐音图；正确项和干扰项都必须让不看文字的孩子独立认出，并与答案语义直接对应。互动页必须使用本课登记的正式图片素材；只有数量点、比较条、笔画轨迹等“形状本身就是知识”的图示可标记 `data-semantic-diagram`，不能拿这个标记给普通插图放行。遮住非目标文字，孩子仍能听题、分辨图片、作答并继续。每个互动页的初始态、答对态、答错提示态和教师示范态都要看截图，出现错图、无关图、风格拼贴、拉伸裁坏或粗糙占位图，一律不能上架。
   **正式图片由负责该课的 agent 制作和验收。** 教学插画、封面、情境图等用 Codex 的图像生成工具制作；Codex 不可用时，用本机已接入的通义画图服务，经 `courseware.tools.media_dispatch` 调用并留请求回执（用户 2026-11-08 同意）。数点、数轴、田字格、几何图和依赖精确数量、位置或笔画的题图用代码绘制，并逐图核对。agent 核对每张正式图的教学含义、数量、位置、清晰度和裁切，保留素材来源、生成提示或绘图源码、文件哈希以及对应的课页和题目。通过 G6 后纳入发布和恢复包。（用户 2026-11-05 明确）

## 三、声音和教材

10. **声音按角色性别**：小数老师男 Ethan，站长猫头鹰女 Cherry，小满男 Aiden，朵朵女 Bella，其他学科以教师档案为准。每句老师的话都有预录音，不叠音、不截断，不用浏览器机械音。
11. **教材准确**：每句老师的话和每道题对照教材核对（儿歌、口诀、符号方向逐字核）。独立核对员（另一个模型）逐句核台词、逐题从头重解，有分歧交人裁决；核对模型必须不同于该课每一个作者模型：Codex 写的课可由 Claude 核对，Claude 写的课由 Codex 或另一个 Claude 模型核对（用户 2026-11-08 同意）。官方资料文字里没有的事实（如笔顺）要先用两个可靠来源核对才能讲，不凭记忆；具体说法和两处资料页码写入 `official-notes.json` 的 `factChecks`，随发布证据一起冻结。页面检查不了的（如笔顺对不对），老师说出顺序并请大人帮看，报告写“待观察”。

## 四、小检查和家长端

12. **小检查**：选项为图片（一二年级）、按教师性别配音读题、每题标知识点 `skill`、有解析、唯一正确答案、不出现"请你自己读题"。题目用新数字、新情境，不重复课上讲解和游戏里练过的例子（那是背例子，不是检查）；正确答案不能集中在同一个位置（超过一半不过，G4）。答题写入学习证据，家长端出报告和薄弱点。
13. **每周测题包**：每课只交"题源"（学习目标、课后练习要点、小检查的知识点，已在 `official-notes.json`、`brief.json` 和小检查里），不单独出测验。每周把孩子这一周学过的所有课合在一起，一次生成一份约 30 分钟的周测：每个学习目标约 2 题原创变式，图片 + 老师配音，独立核题，存档 MinIO，周末推送；没学的课不出题；题量不足如实显示，不凑题。
14. **证据口径**：点击、听完、选对 ≠ 会读会说；报告只写观察到的，口语、纸笔等没有观察到的写"待观察"。

## 五、上架

15. **自动闸门**，`publish_courseware.py check` 全过才能上架：

| 闸门 | 检查什么 |
|---|---|
| G0 | 官方资料笔记齐全，带页码引用 |
| G1 | 每句老师的话都有音频，文件存在、文件名里的哈希对得上，无多余或缺失媒体 |
| G2 | 讲解页文字框不重叠、不出画布 |
| G3 | 互动页铺满 1280×720；老师每页 ≥3 次操作，目标在页面里真实存在；讲解量：讲解页 ≥6 句且 ≥100 字，互动页 ≥5 句且 ≥90 字；讲解页的要点、条目、步骤须按顺序逐个点亮；台词不含带声调的拼音字母；页面自己的元素编号不得与公共框架的编号重名（如 dots、hud、say）；台词、讲解页文字、小检查文字、官方笔记不含繁体字（课件一律用简体） |
| G4 | 小检查：唯一答案、有解析、有 `skill`、有读题音频；一二年级选项是图片；正确答案位置不集中 |
| G5 | 每个角色的声音与性别表一致 |
| G6 | 三种尺寸（1280×720 / 1000×563 / 640×360）脚本试玩：无 JS 报错、无重叠、无截断，可点区域 ≥44px；随机试玩机器人：每个互动页都能点着拖着通关，点“再玩一次”能复位；用游戏引擎的页面先随机乱按乱拖一阵确认不报错，再由引擎自带的自动通关从第 1 关打到最后一关，点“再玩一次”后再通关一遍，回执写明是自动通关；一二年级互动页必须引用本课登记的正式图片，纯知识图示须显式标记 `data-semantic-diagram`；逐页检查初始态、答对态、答错提示态和教师示范态截图，确认图片语义、清晰度、裁切和整课风格；通过后留回执 |
| G7 | 独立核对：台词与教材一致，每题重解答案一致，`skill` 与本课目标对应；逐个学习目标核对老师的话里是否真的讲了（讲了 / 讲得薄 / 没讲，后两种不能上架）。只有所有者明确要求跳过独立复核并直接发布时，才能为当前正文、当前笔记和原核对回执生成一次性 G7 豁免；发布记录必须写“未执行、已豁免”，不得写成“通过”，G0–G6 和 G8 仍必须通过。 |
| G8 | 发布包字段齐全且如实，并通过学生端校验 `validate_release` |

16. **一条命令上架**；发布包字段如实（所有者确认原话 + 自动检查摘要）；若所有者明确豁免 G7，命令必须把原话、确认时间和当前正文哈希冻结进发布凭证，不伪造独立复核或人工听验；同一课时旧版自动下架（保留可回退）。
17. **缺陷变闸门**：抽检发现的每类缺陷，必须补成一条自动检查或本标准里的一句话，才算修好。
   运算符只连接同层级的运算量；把部分移入已表示总数的整体时，用方向箭头表达移动，不能再用加号把该部分重复计入整体。描边、轨迹教学图的路径必须与目标边界相合；圆周、固定距离等需要精确位置的知识图示用代码绘制，不依赖生成插画的几何精度。
   **并行制作归属**（用户 2026-11-05 明确）：每个 agent 同时只负责一个教材版本下的一门完整课程。依次完成全部课时审读、制作、正式图音、G0–G8、正式发布、归档登记、学生端实播及恢复包的独立下载和恢复验证，再接下一课。按教材版本和课程节点登记唯一 owner，若多个节点对应同一官方课目或活动，应先核清覆盖范围并合并重复项。各 owner 独占本课源码、work、媒体缓存和发布包。正式媒体通过统一限流与持久请求回执调用，未对账请求不得自动重发。主控负责分配与共享服务协调，各 owner 依现有授权完成本课制作、配置内的网络调用、发布和验证。
18. **新旧课件统一保存、分阶段迁移**（用户 2026-11-05 批准）：腾讯云正式切换前，完成的课程、媒体和恢复包先进入当前 MinIO，再增量复制到腾讯云 COS；切换完成后，新资源直接进入 COS。上传使用不可变对象键并逐文件回读校验。学生端只通过已登记的对象存储清单或课程媒体接口读取，不能回退到前端 `public/` 或课程本地目录。教材封面、目录卡片、导学图片和配音、小检查图片、周测题包媒体也按此规则保存；通用前端外壳资源（品牌图标、纯装饰纹理、通用头像、书包三维模型）可以随前端发布。
   - **保留可编辑源码**：课件源文件、官方笔记、简要稿、素材清单和必要的发布/付费回执保留；源码也进入恢复备份。播放包不能代替源码。已发布版本的请求、回执、检查记录和正文保持原样。
   - **本地仅保留必要的大文件**：正在制作、修改或被运行程序使用的图片、配音和构建目录保留。完成版本的重复媒体和构建副本，在完整恢复包及第二份独立备份均验证可恢复、远程播放通过、且引用检查证明没有本地消费者后，才按精确路径和 SHA-256 清理。MinIO 与已验证的 COS 副本可以构成两份备份；同一桶里的两个对象键不算两份独立备份。迁移未覆盖到的版本继续保留本地恢复副本。
   - **旧课同样处理**：先核对既有正式归档与制作源文件，补齐缺失备份，不重做课程、不改发布证据、不删除学生可见课程、学习记录和云端正式媒体。尚有缺项或在编辑的版本不进入本地清理清单。
   - **恢复工具与存放位置**：用 `tools/courseware_backup.py` 对明确的稳定源目录创建并校验含路径索引与独立恢复程序的备份，再用 `courseware/tools/store_backup.mjs upload --backup <目录>` 上传到现有 MinIO `study` 桶的 `备份/课件恢复/v1/` 下并完整回读校验；`fetch --receipt <remote-verification.json> --destination <新目录>` 下载后再次验证，随后用包内的 `restore.py` 恢复到独立目录。工具只使用当前存储配置，不创建桶、不修改桶权限、不删除本地或远端文件。用户明确要求沿用原桶，以目录区分恢复资料，不另建备份桶（2026-11-05 更正）。源码补充备份不等于已包含所有正式媒体的完整恢复包。备份和课程一起由现有桶迁移工具复制到 COS；每轮开始时固定对象清单，运行中新增的备份在下一轮增量迁移时补齐。
   - **待上架对象**：正式发布归档注册成功且远程播放验证通过后，按发布归档中的字节身份逐对象删除该版本的 `待上架课件`；禁止按目录前缀扫删，教材封面、目录卡片、书包首页资源、其他课程和正式归档不得随之删除。

## 六、不再要求
