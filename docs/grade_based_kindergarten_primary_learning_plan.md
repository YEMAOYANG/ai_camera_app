# Mira Guardian 幼儿园 / 小学年级分流与 AI 教学方案

更新日期：2026-08-14
状态：动态“先教后练”课程、独立解题与讲解复核、自动发布及 Student Web 学习闭环已实施；摄像头连续语音执行待后续阶段
适用范围：Mira Guardian 家长端 App、Student Web、App Backend、任务系统、AI 内容生成、摄像头教学运行时

## 1. 方案结论

### 当前 V1 实施说明

本分支已实现可运行的小学三科学习 V1：首次设置第 2 步同时采集孩子常用昵称和年级，前后端原子保存昵称与稳定年级编码；小学不会回退幼儿园模板；小学 1—6 年级只开放语文、数学、英语。大多数年级学科各保留 3 个能力边界；一年级语文为保证“a/o/e → 声母与简单音节 → 汉字”进阶而细分为 4 个，当前共 55 个能力边界。能力边界描述学习目标、允许内容、排除内容和先修要求，不包含固定题和答案，也不是题库。

后台按 Asia/Shanghai 时区每天 05:00 根据固定 14 天矩阵确定两个不同学科，并检查孩子对应年级和学科是否有尚未学习的动态课程。没有时，系统把 `gradeCode`、`subject` 和 `skillBoundary` 交给 OpenMAIC generation，由 Kimi 生成包含 `teachingFlow` 和 5 个已验证题对象的“先教后练”候选；随后启动另一次只看公开讲解、`q1` 示范解析与公开题面的 fresh Kimi 验证，并将结果绑定 generation request 与 `publicQuestionHash`。候选通过全部自动质量闸门后，才会自动发布为 `content_origin=openmaic_generated` 并被当天任务选择。服务在 05:00 不在线时恢复后补跑，App 获取今日学习时保留 `GET` 兜底。默认 19:30 和 19:45 是开课时间，不是内容生成时间，家长无需每天配置。

每日两节课按固定 14 天矩阵轮换，28 个课次中语文 10 次、数学 10 次、英语 8 次，同一天不重复学科。同一学科内按孩子自己的受控能力点顺序推进，不由模型、全局课程库存、发布时间或课程 ID 决定：从第一个缺失或尚未 `mastered` 的能力点继续练习，达到掌握后才解锁下一能力点；全部掌握后再按复习到期日和最久未练排序。一年级语文明确为“单韵母 a/o/e → 声母与简单音节 → 汉字与词语 → 完整句子”。OpenMAIC、Kimi 不可用或任一校验失败时，候选保持未发布，系统不会回退到固定题。

Student Web 现按“老师先讲 → 看示范 → 互动引导 → 独立练习 → 总结”执行课程，再进入完成报告。孩子在网页提交回答，程序对 `q2`—`q5` 判题、提示和重试；`q1` 只用于示范，不计分。家长端负责生成学生配对入口、查看进度和报告，并保留必要的协助回退。学习任务、课程版本、会话、4 道计分题的答题尝试、首次独立答对数、提示次数、能力点掌握状态和下次复习日期均持久化，并按家庭隔离。报告来自真实答题记录，不再使用静态示例。

OpenMAIC 已作为受保护的后台动态课程生成器接入：固定使用 `@openmaic/generation@0.3.0` 和 `@openmaic/dsl@0.8.0`，由 Kimi 提供模型回调。题目链首次生成 `teachingFlow`、5 个题对象、预期答案和提示的未验证候选；sidecar 按规范化顺序强制分配 `q1`—`q5`，不信任模型给出的题目 ID。第二次 fresh Kimi 调用只接收公开 `teachingFlow`、无答案字段的 `q1` 示范解析和题目公开字段，不接收候选答案或提示，同时执行独立求解和 `teachingReview`。课堂链再让 OpenMAIC 输出答案盲的 `mira.openmaic.classroom_intent.v2`，仅包含五段意图、受控模板名、素材生产说明和常见误区；HTML、Canvas、JavaScript、动作、URL、评分规则和答案均不得进入输出。Python 后端将意图编译为固定五段 LessonPackage，并再次执行模板白名单、课程边界、题目角色、复盘夸大掌握和答案泄漏检查。任一复核不通过都不能发布；系统而非模型持有最终发布权。

当前 Student Web 提供完整课程流程和学生输入，家长端提供配对、管理、报告与协助回退，摄像头尚未执行连续语音授课。摄像头后续只接入同一学习会话 API、`teachingFlow` 和已发布课程版本，按相同步骤执行，不另建课程或任务系统。

首次孩子建档要求家长同时填写孩子常用昵称并选择“当年 9 月开学后的年级”。昵称和年级缺一不可，必须在同一次请求中校验并原子保存；性别、生日、学校和兴趣不作为首次进入的必填项。

系统根据年级自动进入两种内容模式：

- 幼儿园：成长陪伴、生活习惯、自理、安全、表达、亲子阅读和入学准备。
- 小学：1—6 年级核心能力巩固、学习习惯、自动学习任务和摄像头语音辅导。

小学内容不绑定人教版、苏教版等具体教材，不承诺与学校当天课程同步。当前 55 个能力边界用于限制适龄内容，但仍不是完整课标、完整学年能力图谱或教材同步方案。

移动 App 仍然只面向家长，不提供孩子端移动 App。小学孩子通过独立 Student Web 打开和完成课程；首次登录默认由网页展示二维码，家长使用 App 首页右上角扫码入口，核对两端 4 位数字后授权，一次性配对码作为无法扫码时的兜底。家长 App 继续负责管理任务并查看结果。摄像头接入后可在同一学生身份、课程版本和学习会话上提供语音执行，不取代 Student Web 的图文课件能力。

本方案取代旧文档中以下定义：

- 首次孩子档案必须填写性别和生日。
- 通过生日推算年级。
- 首次设置只支持幼儿园。
- 小学年级无法进入独立内容模式。

本方案不会取消原有幼儿园能力，原有幼儿园模式继续保留并作为独立内容分支。

## 2. 产品边界

### 2.1 本期目标

1. 用孩子常用昵称和一个年级选择完成最小孩子建档。
2. 建立稳定的幼儿园 / 小学内容分流字段。
3. 让系统自动安排每日任务，不要求家长每天配置。
4. 让 Student Web 执行已经发布、可追溯的教学课程包，并为摄像头后续复用同一会话保留接口。
5. 在无内部教师团队的条件下，只开放可确定性判定的小学语文、数学、英语内容。

### 2.2 本期不承诺

- 不承诺同步某个出版社教材。
- 不承诺同步孩子学校当天教学进度。
- 不在首版上线开放式作文、朗读、口语或其他主观评分。
- 不让未经独立求解、确定性校验和发布约束的大模型候选直接教孩子。
- 不让 OpenMAIC 直接连接 Flutter 或摄像头。
- 不新增 `daily_plan`、`daily_flow` 或另一套每日计划业务域。

## 3. 首次进入流程

当前产品流程保持为：

```text
欢迎页
  -> 登录
  -> 家长身份（1 / 2）
  -> 孩子昵称与年级（2 / 2）
  -> 首页
```

孩子昵称与年级是第一个孩子信息步骤，不建议放到登录前。登录和家长身份用于建立家庭空间、权限和数据归属。

### 3.1 孩子昵称与年级页

第 2 步在同一页面收集两个必填字段：孩子常用昵称和“当年 9 月开学后”的年级。常用昵称是摄像头口播、语音对话和家长报告称呼孩子时的第一选择。

页面标题根据当前年份动态生成：

```text
请选择「2026 年 9 月开学后」年级
```

说明文案：

```text
我们会根据年级匹配教学内容和互动方式
```

选项：

| 分组 | 页面展示 | 持久化标签 |
|---|---|---|
| 幼儿园 | 新小班、新中班、新大班 | 小班、中班、大班 |
| 小学 | 新一年级至新六年级 | 一年级至六年级 |

页面规则：

- 孩子常用昵称去除首尾空格后不能为空。
- 全页面只能单选一个年级。
- “新”只用于页面展示，不写入数据库。
- 默认不替家长选择。
- 昵称为空或未选择年级时，“确定”按钮禁用。
- 选择后有明确高亮、语义标签和无障碍选中状态。
- 点击“确定”后，昵称、年级编码和学年在一次请求中提交；服务端必须原子保存，不能出现只保存其中一项的状态。
- 保存中禁用昵称输入、所有年级选项和按钮，防止重复提交。
- 保存失败保留昵称和年级选择并允许重试。
- 中断设置后再次进入，回显已保存或本地暂存的昵称与年级选择。
- 不显示初中、高中、教材版本、性别和生日。
- 学段不单独让家长选择，只能由年级派生为幼儿园或小学。
- 默认采用三列圆角选项；窄屏或大字体模式允许降为两列。
- 页面结构参考用户提供的附图，视觉颜色沿用 Mira 的冷白、信任蓝和深色主按钮体系。

### 3.2 学年规则

- 1—8 月选择时，记录当年 9 月作为生效学年。
- 9—12 月选择时，仍记录当年 9 月作为当前学年起点。
- 每年 7—8 月提醒家长确认下一学年年级。
- 不自动升年级，以兼容留级、跳级、转学和家长修正。

### 3.3 其他孩子资料

以下字段移到“我的 -> 孩子资料”，作为自愿补充项：

- 性别
- 生日
- 学校
- 兴趣
- 常用作息

首次提交的孩子常用昵称可在“我的 -> 孩子资料”中修改，但首次进入时不是可选项。摄像头口播和语音对话必须优先使用已保存昵称；摄像头设备名称和唤醒名是独立字段，不得覆盖孩子昵称。

## 4. 孩子昵称、年级与内容模式数据契约

### 4.1 固定年级编码

```text
kindergarten_small
kindergarten_middle
kindergarten_big
primary_1
primary_2
primary_3
primary_4
primary_5
primary_6
```

客户端在同一个 setup 请求中提交昵称、稳定年级编码和学年：

```json
{
  "nickname": "小米",
  "gradeCode": "primary_3",
  "schoolYearStartYear": 2026
}
```

服务端统一派生学段和中文标签：

```json
{
  "nickname": "小米",
  "gradeCode": "primary_3",
  "gradeLabel": "三年级",
  "educationStageCode": "primary",
  "educationStageLabel": "小学",
  "contentMode": "primary_learning",
  "schoolYearStartYear": 2026,
  "gradeConfirmedAt": 1786400000000
}
```

`educationStageCode` 只允许 `kindergarten` 或 `primary`，由服务端根据 `gradeCode` 派生；客户端不提交第三种学段，也不单独选择学段。

内容模式只允许：

```text
kindergarten_growth
primary_learning
```

Flutter、任务系统和课程系统读取 `gradeCode` 或服务端派生的 `contentMode`，不再自行解析中文年级字符串。Kimi Prompt、摄像头口播和语音运行时同时读取 `nickname`，并将其作为称呼孩子的第一选择。

### 4.2 数据库存储

建议在 `children` 增加：

```text
grade_code
grade_school_year_start
grade_confirmed_at
```

保留现有字段以兼容旧 App 和已有数据：

```text
grade
education_stage
age_stage
birthday
gender
name
nickname
```

后端在过渡期双读双写。旧数据只对能够确定的年级做回填；无法可靠判断的记录保持未确认，并在登录后要求补选一次，不根据生日或年龄猜测。

### 4.3 API 校验

后端必须：

- 拒绝去除首尾空格后为空的昵称。
- 拒绝不在 9 个编码内的年级。
- 拒绝客户端提交相互冲突的年级和学段。
- 在一个事务中校验并保存 `nickname`、`gradeCode` 和 `schoolYearStartYear`；任一字段失败时整次提交失败，不得部分写入。
- 从 `gradeCode` 派生中文标签和 `contentMode`。
- 重选年级时保留已有称呼、生日、性别和其他资料。
- 兼容旧版中文 `educationStage`、`grade` 请求一段过渡期。
- 小学内容未准备好时返回明确的 `contentUnavailable`，不能回退为幼儿园内容。

## 5. 幼儿园与小学内容分流

### 5.1 幼儿园成长模式

幼儿园内容依据教育部《3—6 岁儿童学习与发展指南》的健康、语言、社会、科学、艺术五类发展方向构建，不做小学化抢跑。

| 年级 | 主要内容 |
|---|---|
| 小班 | 作息、安全、表达需求、简单收纳、亲子阅读 |
| 中班 | 自理、规则、情绪表达、观察分类、故事复述 |
| 大班 | 入学准备、任务意识、数感、语言表达、书包整理 |

保留已有幼儿园产品原则：任务少而稳定、生活场景优先、低打扰提醒、今日节奏和家长确认优先。

### 5.2 小学学习模式

小学内容参考教育部《义务教育课程方案和课程标准（2022 年版）》建立通用年级能力边界，不跟随具体教材版本，也不表示已完成整套课标覆盖。

| 年级段 | 核心内容 |
|---|---|
| 一至二年级 | 语文识字与词句、数学数感与基础运算、Mira 英语拓展词汇与基础句型 |
| 三至四年级 | 语文词句与客观阅读、数学运算与应用题、英语词汇与句型理解 |
| 五至六年级 | 语文客观阅读与语言运用、数学问题解决、英语语篇与语法基础 |

V1 只开放上述三科中能够通过受控答案确定性判定的题型。作文、朗读、口语以及需要主观判断的阅读表达不进入孩子运行时。

一、二年级英语是为了满足产品从一年级开始覆盖三科的 Mira 拓展内容，不代表国家统一开设要求，也不代表与当地教材同步。

小学内容分成两条路径：

1. 通用能力课程：系统按年级、诊断结果和掌握度自动安排。
2. 单题辅导：孩子把一道自己持有的题目放到指定区域，系统只针对该题分步提示。

产品对外表述使用“年级核心能力巩固”或“AI 学习教练”，不使用“同步教材课堂”或“完全替代教师”。

## 6. 无内部教师团队时的内容生产

### 6.1 基本原则

没有内部教师，不等于让模型不经约束直接发布。OpenMAIC 和 Kimi 提供候选与独立解题证据；最终能否发布由确定性校验、内容边界、去重规则和数据库约束共同决定。

首版只做可确定性判定的小学语文、数学、英语：

```text
受控年级能力边界（不是题库）
  -> OpenMAIC generation + Kimi 生成 teachingFlow + 5 个题对象
  -> q1 不计分示范；q2-q3 互动引导；q4-q5 独立练习
  -> fresh Kimi 只看公开讲解和公开题面，独立解题并复核教学讲解
  -> requestId + publicQuestionHash 绑定两次调用
  -> 自动质量闸门和数据库唯一约束
  -> 自动发布 content_origin=openmaic_generated
  -> 每日任务只选择该来源
```

能力边界负责限定：

- 知识点
- 先修能力
- 年级学习目标
- 允许和排除内容

后端验证策略另外限定白名单题型、规范化规则、答案一致性和掌握标准。

首次 OpenMAIC generation + Kimi 负责生成候选：

- 一个符合 `mira.learning.teaching-flow.v1` 的 `teachingFlow`，包含短讲解、1—3 个关键点、5 个题对象的角色引用和课后总结
- 5 个适龄、可确定性判定的题对象：`q1` 为不计分示范，`q2`—`q3` 为互动引导，`q4`—`q5` 为独立练习
- 候选答案、选项或可接受答案集合
- 一级提示
- 受控题型和标准化规则

候选 `teachingFlow` 本身不包含答案字段，也不能直接说出 `q2`—`q5` 的答案或正确选项标签。后端从已验证的 `q1` 构造公开 `workedExample={questionId:'q1',explanation}` 供示范展示和 fresh 复核；其中没有答案字段，解析必须是非空纯文本且最长 1500 字符。sidecar 根据规范化后的 5 个题对象强制设置 `q1`—`q5` 及其角色引用，不信任模型给出的题目 ID。

第二次 fresh Kimi 验证只接收公开 `teachingFlow`、公开 `workedExample`、题目 ID、题型、题干和必要选项，不接收候选答案、提示或评分字段。除独立求解题目外，还必须输出 `teachingReview={passed,issues}`，复核讲解与示范解析是否越出能力边界、是否存在事实错误、是否适合该年龄，以及讲解与总结是否泄露 `q2`—`q5` 的答案或正确选项标签。该结果必须与原 generation request 和公开题面的 `publicQuestionHash` 绑定，避免拿另一套题或携带答案进行“自证”。模型调用本身没有发布权限；只有 `teachingReview.passed=true` 且后端全部校验通过后才自动发布。

### 6.2 自动质量闸门

- 严格 JSON Schema、固定 5 个题对象、`q1`—`q5` 角色引用和白名单题型校验
- `gradeCode`、`subject`、`skillBoundary`、先修能力和允许 / 排除内容校验
- 语文、英语固定答案、可接受答案、单选和顺序题的一致性校验
- 题干、提示、讲解和总结是否直接泄露答案或正确选项标签
- 数学表达式从题干重新派生并用程序重算，不信任候选自带算式
- fresh Kimi 独立解题与候选答案一致性校验
- fresh Kimi 对教学边界、事实正确性、年龄适配和答案泄露的 `teachingReview` 必须通过
- `workedExample.questionId` 必须为 `q1`，示范解析必须经 fresh Kimi 复核且不能携带答案、媒体或动作字段
- generation request 与 `publicQuestionHash` 绑定校验
- 课程级语义指纹去重、题目指纹去重和数据库唯一约束
- 语言长度、课程时长、儿童安全和敏感内容检查
- Prompt、模型、来源、请求、哈希、校验报告和内容版本记录

fresh Kimi 解题只是必要证据之一，不能替代程序重算和其他确定性闸门。

### 6.3 内容扩展条件

- 当前只定位为语文、数学、英语三科“年级核心能力练习”，不宣称同步教材、学校进度或完整课标。
- 55 个能力边界不是 55 门固定课程，也不是题库；每一道生产题都来自受控动态生成，并在发布前经过同一质量闸门。
- 如引入外部内容，应取得商用授权、答案、年级标签和可改编权；可使用外部兼职教师做模板级或抽样审核，不要求教师每天审核每个孩子的课程。
- 开放式作文、朗读、口语、主观阅读表达等评分在获得可靠内容与独立审核能力前不上线。

## 7. Kimi 与 OpenMAIC 的接入边界

### 7.1 Kimi

继续使用 Mira Backend 现有 AI Provider 配置，但课程生成与 fresh 独立解题使用分离的请求：

- 长输出
- 固定 JSON 结构
- 更长超时
- 重试和失败队列
- Prompt 版本
- 低随机性
- 成本与延迟记录
- 生成来源和模型版本追踪
- 公开题面哈希与请求绑定

课程生成不得复用当前短对话接口的默认参数。

### 7.2 OpenMAIC

OpenMAIC 只作为可替换的后台候选课程生成组件：

- 输入已经确定的 `gradeCode`、`subject` 和 `skillBoundary`。
- 通过 generation + Kimi 生成 `teachingFlow` 与固定 5 个题对象的未验证候选课程。
- 强制将规范化后的 `q1` 设为不计分示范、`q2`—`q3` 设为互动引导、`q4`—`q5` 设为独立练习；不信任模型题目 ID。
- 输出转换为 Mira 自己的候选课程结构，状态保持 `unverified`。
- 不进入 Flutter。
- 不直接连接摄像头。
- 不接收孩子运行时评分数据。
- 不作为课程标准、固定题库或最终发布决策来源。
- 不接管 Mira 的账号、儿童数据、模型配置和 Prompt 管理。

后端随后使用同一 Provider 配置发起独立的 fresh Kimi 验证，只发送公开 `teachingFlow`、无答案字段的 `q1` 示范解析和公开题面；该步骤不经由原候选答案回填。验证结果同时包含独立解题和 `teachingReview`，后者不通过时候选不得发布。候选只有通过 Mira 的全部确定性校验和数据约束后才会自动发布。

当前生产链路为：

```text
Mira Backend
  -> OpenMAIC generation + Kimi 生成 teachingFlow + 5 个题对象
  -> 后端补充 q1 公开示范解析（无答案字段）
  -> fresh Kimi 只看公开讲解、示范解析和公开题面，独立解题 + teachingReview
  -> Mira 自动质量闸门
  -> learning_courses(content_origin=openmaic_generated)
```

## 9. 每日任务自动生成

家长不需要每天安排课程。首次完成孩子常用昵称与年级设置后，V1 自动执行以下规则：

1. 后台按 Asia/Shanghai 时区每天 05:00 为全部小学孩子幂等准备两节课。
2. 服务在 05:00 不在线时，恢复后的首次检查会补跑；App 调用 `GET /api/learning/today` 时仍保留请求级兜底。
3. 固定 14 天矩阵共 28 个课次：语文 10 次、数学 10 次、英语 8 次；同一天的两节课学科不重复。
4. 对当天每个学科，先检查该孩子对应 `gradeCode` 下尚未学习的 `content_origin=openmaic_generated` 课程。
5. 没有可用课程时，选择一个受控 `skillBoundary`，把 `gradeCode`、`subject` 和完整边界交给 OpenMAIC generation + Kimi，生成含 `teachingFlow` 和 5 个题对象的候选；5 个对象按 `q1` 示范、`q2`—`q3` 引导、`q4`—`q5` 独立练习分工，不等于 5 道计分练习。
6. 使用另一个 fresh Kimi 请求仅对公开讲解、无答案字段的 `q1` 示范解析和公开题面进行独立验证，以 generation request 和 `publicQuestionHash` 绑定结果；只有 `teachingReview.passed=true`，且候选通过确定性校验、泄漏检查、数学题干派生算式重算、语义去重及数据库唯一约束后才自动发布。
7. 只从对应年级、对应学科且 `content_origin=openmaic_generated` 的已发布课程中选课，并在现有 `tasks` 中幂等创建两个 `learning` 任务。
8. OpenMAIC、Kimi 不可用或任一验证失败时不发布候选、不创建引用无效课程的任务，也不回退生产固定题。
9. 两节课默认开课时间为 19:30 和 19:45；这两个时间只表示 `scheduledAt`，不表示课程内容生成。
10. 当前到时间后由孩子在 Student Web 启动或恢复课程，按“老师先讲 → 看示范 → 互动引导 → 独立练习 → 总结”完成；家长端保留协助回退。运行时只对 `q2`—`q5` 共 4 题计分，并记录回答、提示次数、错因和掌握结果。摄像头接入后在同一会话中承担邀请、口播和收音，不改变课程或计分规则。

05:00 的每日准备会在缺少未学动态课时调用模型，而不是只从固定目录选课。App `GET` 兜底执行同样的检查和生成规则。学习时长、可学习时间段、周末暂停或请假可作为后续一次性设置扩展，但不要求家长每日配置。

任务只引用：

```text
lessonPackageId
lessonPackageVersion
skillId
learningSlot
scheduledAt
```

所有每日安排继续属于现有 `tasks`，不创建新的日计划域。

## 10. 摄像头教学运行时

当前 App 和未来摄像头必须执行同一已发布课程包与学习会话，固定教学顺序为：

```text
teach（老师先讲）
  -> q1（看示范，不计分）
  -> q2-q3（互动引导）
  -> q4-q5（独立练习）
  -> recap（总结）
```

摄像头接入后将上述步骤转换成设备可执行动作：

```text
say
ask
listen
evaluate
hint
retry
capture
finish
escalate
```

首版适合：

- 口算
- 固定答案的文字问答
- 单选题
- 顺序题
- 有明确可接受答案集合的语文、英语客观题
- 大字学习卡
- 在场和专注判断

当前房间广角摄像头不能稳定读取书本小字、算式和笔迹。纸面数学、汉字书写和作文批改需要桌面近距离视角，或者要求孩子把题目放入明确的识别区域。摄像头可以播放朗读或口语引导，但 V1 不对作文、朗读、口语或复述做主观评分。

摄像头教学运行时仍需 Mira 自己提供：

- 流式 ASR / TTS
- VAD
- 打断和继续
- AEC 回声消除
- 会话状态恢复
- 纸面区域识别
- 隐私与数据保留策略

OpenMAIC 不解决这些实时设备能力。

每次摄像头口播或语音会话开始前，运行时从孩子档案读取已保存的常用昵称，并优先用该昵称称呼孩子；设备显示名、摄像头唤醒名和年级标签不能替代孩子昵称。

## 12. 当前实现与剩余风险

## 14. 上线门槛

### 14.1 首次设置

- 只出现幼儿园和小学 9 个选项。
- 孩子常用昵称与年级同时必填；不要求性别和生日。
- 单选、禁用、保存中、错误、恢复状态完整。
- 昵称、年级编码和学年原子保存，不能部分成功。

### 14.2 数据与内容路由

- 非法年级无法写入。
- 年级与学段不会冲突。
- 重选年级不清空已有资料。
- 小学用户绝不获得幼儿园模板。
- 内容未准备好时返回明确状态。

### 14.3 内容质量

- 数学答案可程序重算，语文和英语答案只能使用白名单确定性评分器。
- fresh Kimi 只能看到公开题面，且解题结果必须与 generation request 和 `publicQuestionHash` 一致。
- fresh Kimi 必须复核公开讲解和 `q1` 示范解析的边界、事实与年龄适配；`teachingReview` 不通过即禁止发布。
- 题干答案泄漏、数学题干派生算式、题目与课程语义重复均有自动阻断。
- 严重事实错误、答案错误和严重超纲错误为 0。
- 每个课程和报告结论可追溯到课程包版本和孩子回答。
- 运行时不自由生成未经验证的核心教学内容。
- 任何模型或校验故障都不得发布候选，也不得回退固定题。

### 14.4 学生 Web、家长与摄像头

- 家长不需要每天配置学习任务。
- 当前孩子在 Student Web 执行“讲解 → 示范 → 引导 → 独立练习 → 总结”；家长 App 负责配对、管理、报告和必要的协助回退，摄像头后续执行同一已发布课程包和会话。
- 无回答、答错、连续失败和设备离线都有降级策略。
- 儿童音视频遵循最小采集、最短保留和监护人可控原则。
