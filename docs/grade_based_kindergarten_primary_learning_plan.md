# Mira Guardian 幼儿园 / 小学年级分流与 AI 教学方案

更新日期：2026-08-11
状态：方案待确认，尚未进入代码实施
适用范围：Mira Guardian 家长端 App、App Backend、任务系统、AI 内容生成、摄像头教学运行时

## 1. 方案结论

首次孩子建档只要求家长选择“当年 9 月开学后的年级”。性别、生日、孩子称呼、学校和兴趣均不再作为首次进入的必填项。

系统根据年级自动进入两种内容模式：

- 幼儿园：成长陪伴、生活习惯、自理、安全、表达、亲子阅读和入学准备。
- 小学：1—6 年级核心能力巩固、学习习惯、自动学习任务和摄像头语音辅导。

小学内容不绑定人教版、苏教版等具体教材，不承诺与学校当天课程同步；内容边界依据国家课程标准和 Mira 自有年级能力图谱确定。

App 仍然只面向家长。孩子不需要安装或操作孩子端 App，主要通过摄像头语音与教学任务互动。

本方案取代旧文档中以下定义：

- 首次孩子档案必须填写性别、生日和称呼。
- 通过生日推算年级。
- 首次设置只支持幼儿园。
- 小学年级无法进入独立内容模式。

本方案不会取消原有幼儿园能力，原有幼儿园模式继续保留并作为独立内容分支。

## 2. 产品边界

### 2.1 本期目标

1. 用一个年级选择完成最小孩子建档。
2. 建立稳定的幼儿园 / 小学内容分流字段。
3. 让系统自动安排每日任务，不要求家长每天配置。
4. 让摄像头执行已经发布、可追溯的教学课程包。
5. 在无内部教师团队的条件下，先从可程序验证的小学数学内容开始。

### 2.2 本期不承诺

- 不承诺同步某个出版社教材。
- 不承诺同步孩子学校当天教学进度。
- 不在首版上线开放式作文批改和主观阅读评分。
- 不让大模型临时自由生成一整节核心课程后直接教孩子。
- 不让 OpenMAIC 直接连接 Flutter 或摄像头。
- 不新增 `daily_plan`、`daily_flow` 或另一套每日计划业务域。

## 3. 首次进入流程

当前产品流程保持为：

```text
欢迎页
  -> 登录
  -> 家长身份（1 / 2）
  -> 年级选择（2 / 2）
  -> 首页
```

年级选择是第一个孩子信息步骤，不建议放到登录前。登录和家长身份用于建立家庭空间、权限和数据归属。

### 3.1 年级选择页

页面标题根据当前年份动态生成：

```text
请选择「2026 年 9 月开学后」年级
```

说明文案：

```text
我们会根据年级匹配教学内容和互动方式
```

选项：

| 分组 | 页面展示 | 持久化标签 |
|---|---|---|
| 幼儿园 | 新小班、新中班、新大班 | 小班、中班、大班 |
| 小学 | 新一年级至新六年级 | 一年级至六年级 |

页面规则：

- 全页面只能单选一个年级。
- “新”只用于页面展示，不写入数据库。
- 默认不替家长选择。
- 未选择时“确定”按钮禁用。
- 选择后有明确高亮、语义标签和无障碍选中状态。
- 保存中禁用所有选项和按钮，防止重复提交。
- 保存失败保留选择并允许重试。
- 中断设置后再次进入，回显已保存或本地暂存选择。
- 不显示初中、高中、教材版本、性别和生日。
- 默认采用三列圆角选项；窄屏或大字体模式允许降为两列。
- 页面结构参考用户提供的附图，视觉颜色沿用 Mira 的冷白、信任蓝和深色主按钮体系。

### 3.2 学年规则

- 1—8 月选择时，记录当年 9 月作为生效学年。
- 9—12 月选择时，仍记录当年 9 月作为当前学年起点。
- 每年 7—8 月提醒家长确认下一学年年级。
- 不自动升年级，以兼容留级、跳级、转学和家长修正。

### 3.3 其他孩子资料

以下字段移到“我的 -> 孩子资料”，作为自愿补充项：

- 孩子称呼
- 性别
- 生日
- 学校
- 兴趣
- 常用作息

首次未填写称呼时，由后端建立系统显示名，摄像头统一称呼“小朋友”；同时记录称呼尚未由家长补充，不能让 Flutter 暗中伪造家长输入。

## 4. 年级与内容模式数据契约

### 4.1 固定年级编码

```text
kindergarten_small
kindergarten_middle
kindergarten_big
primary_1
primary_2
primary_3
primary_4
primary_5
primary_6
```

客户端只提交稳定编码和学年：

```json
{
  "gradeCode": "primary_3",
  "schoolYearStartYear": 2026
}
```

服务端统一派生学段和中文标签：

```json
{
  "gradeCode": "primary_3",
  "gradeLabel": "三年级",
  "educationStageCode": "primary",
  "educationStageLabel": "小学",
  "contentMode": "primary_learning",
  "schoolYearStartYear": 2026,
  "gradeConfirmedAt": 1786400000000
}
```

内容模式只允许：

```text
kindergarten_growth
primary_learning
```

Flutter、任务系统、课程系统、Kimi Prompt 和摄像头运行时都读取 `gradeCode` 或服务端派生的 `contentMode`，不再自行解析中文年级字符串。

### 4.2 数据库存储

建议在 `children` 增加：

```text
grade_code
grade_school_year_start
grade_confirmed_at
```

保留现有字段以兼容旧 App 和已有数据：

```text
grade
education_stage
age_stage
birthday
gender
name
nickname
```

后端在过渡期双读双写。旧数据只对能够确定的年级做回填；无法可靠判断的记录保持未确认，并在登录后要求补选一次，不根据生日或年龄猜测。

### 4.3 API 校验

后端必须：

- 拒绝不在 9 个编码内的年级。
- 拒绝客户端提交相互冲突的年级和学段。
- 从 `gradeCode` 派生中文标签和 `contentMode`。
- 重选年级时保留已有称呼、生日、性别和其他资料。
- 兼容旧版中文 `educationStage`、`grade` 请求一段过渡期。
- 小学内容未准备好时返回明确的 `contentUnavailable`，不能回退为幼儿园内容。

## 5. 幼儿园与小学内容分流

### 5.1 幼儿园成长模式

幼儿园内容依据教育部《3—6 岁儿童学习与发展指南》的健康、语言、社会、科学、艺术五类发展方向构建，不做小学化抢跑。

| 年级 | 主要内容 |
|---|---|
| 小班 | 作息、安全、表达需求、简单收纳、亲子阅读 |
| 中班 | 自理、规则、情绪表达、观察分类、故事复述 |
| 大班 | 入学准备、任务意识、数感、语言表达、书包整理 |

保留已有幼儿园产品原则：任务少而稳定、生活场景优先、低打扰提醒、今日节奏和家长确认优先。

### 5.2 小学学习模式

小学内容依据教育部《义务教育课程方案和课程标准（2022 年版）》建立通用年级能力课程，不跟随具体教材版本。

| 年级段 | 核心内容 |
|---|---|
| 一至二年级 | 数感、基础运算、朗读、识字巩固、学习启动、小书包 |
| 三至四年级 | 运算、应用题、阅读理解、英语朗读、错因识别 |
| 五至六年级 | 数学问题解决、阅读表达、英语理解、自主计划、复习策略 |

小学内容分成两条路径：

1. 通用能力课程：系统按年级、诊断结果和掌握度自动安排。
2. 单题辅导：孩子把一道自己持有的题目放到指定区域，系统只针对该题分步提示。

产品对外表述使用“年级核心能力巩固”或“AI 学习教练”，不使用“同步教材课堂”或“完全替代教师”。

## 6. 无内部教师团队时的内容生产

### 6.1 基本原则

没有内部教师，不等于可以让模型自由生成并自动发布。OpenMAIC 和 Kimi 都是生成工具，不是内容正确性的来源。

首版优先做可程序验证的小学数学：

```text
年级能力点
  -> 参数化题目和确定答案
  -> Kimi 生成适龄讲解、三级提示和鼓励话术
  -> 自动质量校验
  -> 发布 LessonPackage
  -> 每日任务选择
```

系统负责：

- 知识点
- 先修能力
- 难度范围
- 题目参数
- 标准答案
- 掌握标准

Kimi 负责：

- 适龄解释
- 生活化示例
- 分层提示
- 错误后的反馈
- 摄像头口播脚本

Kimi 不得改变知识点、题目、答案和掌握规则。

### 6.2 自动质量闸门

- JSON Schema 校验
- 年级和知识点允许列表
- 先修能力校验
- 数学答案程序重算
- 题目唯一答案和歧义检查
- 重复题检查
- 提示是否泄露答案
- 语言长度与年级阅读难度
- 课程时长
- 儿童安全与敏感内容
- Prompt、模型、来源和内容版本记录

让 Kimi 再审核 Kimi 只能作为辅助，不能视为独立正确性证明。

### 6.3 内容扩科条件

- 如果没有教师或授权内容库，首版只定位为“AI 数学练习教练”。
- 如果要同时开放 1—6 年级语文和英语，应购买带商用授权、答案、年级标签和可改编权的内容。
- 可使用外部兼职教师做模板级或抽样审核，不要求教师每天审核每个孩子的课程。
- 开放式作文、主观阅读和复杂口语评分在获得可靠内容与审核能力前不上线。

## 7. Kimi 与 OpenMAIC 的接入边界

### 7.1 Kimi

继续使用 Mira Backend 现有 AI Provider 配置，但为课程生成新增独立异步能力：

- 长输出
- 固定 JSON 结构
- 更长超时
- 重试和失败队列
- Prompt 版本
- 低随机性
- 成本与延迟记录
- 生成来源和模型版本追踪

课程生成不得复用当前短对话接口的默认参数。

### 7.2 OpenMAIC

OpenMAIC 只作为可替换的后台课程草稿生成组件：

- 输入已经确定的能力点和边界。
- 生成课程大纲、讲解顺序、问题和互动草稿。
- 输出转换为 Mira 自己的 `lesson_package.v1`。
- 不进入 Flutter。
- 不直接连接摄像头。
- 不作为课程标准、题库或标准答案来源。
- 不接管 Mira 的账号、儿童数据、模型配置和 Prompt 管理。

先对比两条 PoC：

```text
A：Mira Backend 直接调用 Kimi
B：OpenMAIC generation + Kimi
```

如果 B 不能明显降低内容制作、校验和返工成本，则不增加 OpenMAIC 依赖。

## 8. 课程包与学习数据

### 8.1 `LessonPackage`

```text
id
version
status
gradeCode
subject
skillId
learningObjectives
prerequisites
explainSteps[]
questions[]
expectedAnswers[]
hints[]
misconceptionTags[]
spokenScript
masteryRule
sourceRefs[]
modelVersion
promptVersion
publishedAt
```

课程状态：

```text
draft -> validating -> approved -> published -> retired
```

没有通过自动验证的课程不能进入 `published`。

### 8.2 学习域模型

- `CurriculumNode`：年级能力点、先修关系、难度和允许范围。
- `LessonPackage`：可执行的版本化课程包。
- `LearningSession`：一次摄像头教学会话。
- `LearningTurn`：老师与孩子的一轮互动。
- `LearningAttempt`：孩子的回答、提示次数和错误类型。
- `MasteryState`：知识点掌握度和下一次复习时间。
- `ContentGenerationJob`：Kimi / OpenMAIC 生成作业和校验状态。

## 9. 每日任务自动生成

家长不需要每天安排课程。首次只选年级，后续仅提供一次性轻设置：

- 每天学习时长
- 可学习时间段
- 周末是否安排
- 优先学科
- 暂停或请假

系统每天：

1. 读取 `gradeCode`、诊断结果和掌握状态。
2. 选择一个复习能力点。
3. 选择一个新能力点。
4. 从已发布课程包中选课。
5. 在现有 `tasks` 中创建学习任务。
6. 到时间后由摄像头邀请孩子开始。
7. 记录回答、提示次数、错因和掌握结果。
8. 向家长生成简短报告。

任务只引用：

```text
lessonPackageId
lessonPackageVersion
skillId
scheduledAt
```

所有每日安排继续属于现有 `tasks`，不创建新的日计划域。

## 10. 摄像头教学运行时

课程包转换成设备可执行动作：

```text
say
ask
listen
evaluate
hint
retry
capture
finish
escalate
```

首版适合：

- 口算
- 口头问答
- 朗读
- 复述
- 口头选择题
- 大字学习卡
- 在场和专注判断

当前房间广角摄像头不能稳定读取书本小字、算式和笔迹。纸面数学、汉字书写和作文批改需要桌面近距离视角，或者要求孩子把题目放入明确的识别区域。

摄像头教学运行时仍需 Mira 自己提供：

- 流式 ASR / TTS
- VAD
- 打断和继续
- AEC 回声消除
- 会话状态恢复
- 纸面区域识别
- 隐私与数据保留策略

OpenMAIC 不解决这些实时设备能力。

## 11. 家长端体验

### 11.1 幼儿园首页

- 今日节奏
- 当前看护状态
- 生活任务
- 摄像头观察
- 需要家长确认的事项
- 最少文字和操作

### 11.2 小学首页

- 今日学习任务
- 当前正在巩固的能力点
- 下一次学习时间
- 是否需要家长处理
- 最近一次学习简报

### 11.3 学习报告

报告优先展示：

- 学了什么
- 是否独立完成
- 使用了几次提示
- 常见错误
- 下次复习什么
- 是否需要家长帮助

不默认展示排名、同龄比较和焦虑化结论。

## 12. 当前代码必须先解决的兼容风险

1. 当前任务模板只支持小班、中班、大班；小学年级解析失败后可能静默回退成小班。
2. 当前“我的 -> 孩子资料”初始化时固定为幼儿园，小学资料可能在保存时被改回幼儿园。
3. 当前 setup 接口没有严格校验年级和学段组合。
4. 当前 Flutter 把生日和孩子称呼设为首次提交条件，后端生日本身已经允许为空。
5. 当前语音会话 Prompt 仍明确面向幼儿园。
6. 当前课程、学习会话、答题尝试和掌握度数据域尚不存在。

只修改年级选择页面不能达到内容分流目标。页面、后端年级合同、任务模板和内容路由必须作为同一个上线门槛。

## 13. 实施阶段

### 阶段 1：年级基础

- 年级编码与学年字段
- 旧数据迁移与双读双写
- 年级选择页
- setup 接口校验
- 孩子资料编辑兼容小学
- 移除小学回退幼儿园的逻辑
- 幼儿园 / 小学明确空状态

验收：小学选择永远不会进入幼儿园模板。

### 阶段 2：内容路由

- `contentMode`
- 小学基础任务模板
- `CurriculumNode`
- `LessonPackage`
- `LearningSession`
- `LearningAttempt`
- `MasteryState`

验收：每个公开可选择年级至少有完整、非空、适龄的首页和任务体验。

### 阶段 3：小学数学 PoC

- 先选三年级 20 个能力点
- 对比直接 Kimi 与 OpenMAIC + Kimi
- 文字模拟孩子回答
- 跑通提示、重试、掌握判定和报告
- 验证内容正确率、人工返工、成本和延迟

验收：严重事实错误、答案错误和超纲错误为 0。

### 阶段 4：摄像头教学

- 连续语音会话状态机
- 流式 ASR / TTS
- VAD、打断、AEC
- 课程动作执行
- 学习事件回传
- 家长报告

验收：断网、打断、无回答、识别失败和家长接管都有明确降级路径。

### 阶段 5：扩年级与扩科

- 补齐一至六年级基础数学包
- 所有年级达到公开上线门槛后再解除小学功能开关
- 获得内容授权或外部审核能力后扩展语文和英语
- 引入近距离纸面识别后再扩展书写型任务

## 14. 上线门槛

### 14.1 首次设置

- 只出现幼儿园和小学 9 个选项。
- 不要求性别、生日和孩子称呼。
- 单选、禁用、保存中、错误、恢复状态完整。
- 年级编码和学年正确保存。

### 14.2 数据与内容路由

- 非法年级无法写入。
- 年级与学段不会冲突。
- 重选年级不清空已有资料。
- 小学用户绝不获得幼儿园模板。
- 内容未准备好时返回明确状态。

### 14.3 内容质量

- 数学标准答案可程序重算。
- 严重事实错误、答案错误和严重超纲错误为 0。
- 每个课程和报告结论可追溯到课程包版本和孩子回答。
- 运行时不自由生成未经验证的核心教学内容。

### 14.4 家长与摄像头

- 家长不需要每天配置学习任务。
- 摄像头只执行已发布课程包。
- 无回答、答错、连续失败和设备离线都有降级策略。
- 儿童音视频遵循最小采集、最短保留和监护人可控原则。
