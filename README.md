# Mira Guardian（米拉）家长端 App

Mira Guardian（米拉）家长端 App 是 AI 智护摄像头产品的家长管理入口。这个 App 只面向家长使用，用来完成设备绑定、孩子档案、任务设置、任务提醒、实时看护、报告、积分、打卡、安全告警、隐私设置和家庭成员管理。

本 README 只描述家长端 App 的产品功能、页面内容、MVP 范围和开发计划。更完整的需求来源见 [docs/ai_camera_parent_needs_product_tech_plan.md](docs/ai_camera_parent_needs_product_tech_plan.md)。

当前仓库已在 `mobile/` 初始化 Flutter 工程，本文档继续作为家长端 App 的产品与研发入口。

## Flutter 工程入口

```bash
cd mobile
flutter pub get
flutter run
```

验证命令：

```bash
cd mobile
flutter analyze
flutter test
```

当前工程采用 Flutter + Riverpod + go_router + Dio 的组合，先搭好首页、任务、实时看护、告警和我的五个家长端主入口。框架选型记录见 [docs/flutter_framework_decision.md](docs/flutter_framework_decision.md)。

## App 后端接口

当前仓库已新增 `backend/` 作为家长端 App 的接口服务，承载手机号验证码登录、access/refresh token 登录态、session 查询、首次设置、任务、积分、奖励、设备状态，以及摄像头/AI/OTA 的后端 adapter 边界。

后端启动：

```bash
cd backend
python3 -m pip install -r requirements.txt
python3 app.py
```

接口说明见 [docs/backend_api.md](docs/backend_api.md)。Flutter 只调用 App 后端接口，不直接接触底层流媒体、RTSP/go2rtc、硬件私有协议、短信供应商或 AI provider key。旧测试运行时只能作为 development/test adapter 显式启用，不能成为 production 主路径。

## App 定位

家长端 App 的核心目标是解放家长，把“盯作业、反复催、陪玩、检查任务、提醒睡觉、确认安全”这些高频重复劳动交给摄像头和 App 的任务系统。家长不需要一直盯着孩子，也不需要每件小事都亲自催；家长主要负责设置规则、处理异常、确认重要结果和给孩子真实的情感支持。

产品不是要替代家长，也不是把孩子交给 AI 管教。米拉要做的是一个温柔、稳定、有边界的家庭陪伴者：用任务提醒、状态观察、鼓励话术和报告摘要，帮助孩子逐步养成自启动、自整理、自休息、自求助的好习惯。

App 首页需要优先回答三个问题：

1. 孩子现在在哪里、在做什么、状态是否正常？
2. 接下来最需要关注的一件事是什么？
3. 有没有需要家长立即处理的异常或确认？

首版 App 不做孩子端娱乐入口，不把孩子引导到手机里长时间操作。孩子主要通过摄像头语音互动，家长通过 App 管规则、看结果、处理异常。奖励兑换这类孩子主动诉求也先走摄像头语音：孩子可以对摄像头说“我想换奖励”，摄像头只负责识别和转交给家长确认，不直接承诺兑换结果。

## 目标用户

| 用户 | 需求 | App 价值 |
|---|---|---|
| 父母 | 想知道孩子现在是否安全、是否在做该做的事 | 首页状态、任务、日报、实时看护 |
| 主要照护人 | 需要设置提醒、奖励、任务和安全规则 | 任务模板、任务规则、奖励规则、紧急联系人 |
| 异地家长 | 不能一直在孩子身边，但想及时知道异常 | 推送、实时看护、事件摘要、安全告警 |
| 共同照护成员 | 需要查看有限信息或协助处理任务 | 家庭成员权限、角色管理、通知分发 |
| 祖辈/其他家人 | 需要按家长规则协助照护，但不需要看到全部隐私 | 待办交接、有限权限、事件处理记录 |

## 教育原则

产品默认采用鼓励式教育，不采用羞辱、比较、恐吓或高频唠叨。

原则：

- 少催促：每次提醒只给一个小动作，例如“先把书放到桌上”。
- 多鼓励：表扬具体行为，例如“你刚才自己回到座位了”。
- 有边界：任务、聊天、故事、音乐和陪玩都有时长、次数和免打扰规则。
- 帮孩子自启动：先提醒孩子自己开始，再升级给家长处理。
- 帮家长省心：只把异常、证据确认、奖励兑换申请、兑现提醒和安全事件推给家长。
- 不替孩子做：作业辅导只引导思路，不直接报答案或代写。
- 奖励可淡出：积分和奖励用于建立习惯，习惯稳定后应减少外部奖励，转向成就感、亲子肯定和自主权。

## 核心功能

### 首页

首页是家长打开 App 后的状态页，不应该首先呈现一堆功能入口或百分比。它要让家长一眼知道“孩子现在怎么样”，再告诉家长是否需要介入。

内容包括：

- 设备在线状态、隐私模式、画面/语音可用状态。
- 孩子当前状态：所在区域、正在做什么、是否有人陪同、状态是否正常。
- 当前任务：例如“数学作业进行中”“晚饭任务中”“睡前洗漱未开始”“未识别到孩子”。
- 下一步：距离下一个提醒、休息、确认、睡前目标或小书包提醒还有多久。
- 风险与异常：离座过久、长时间未出现、陌生人/门口声音、安全区域触发、设备离线。
- 家长待处理：任务证据确认、奖励兑换申请、兑现提醒、安全事件处理、打卡素材审核。
- 必要快捷入口：实时看护、音频通话、任务、待处理事项。

首页不展示“任务完成率”和“任务数量”作为主信息，因为这些数字对家长即时决策帮助有限。进度可以放在任务页和日报里；首页只突出当前状态、下一步和需要家长处理的事。

### 设备绑定与家庭管理

家长端需要支持完整的首次使用流程。

内容包括：

- 登录或注册。
- 设置当前家长身份：妈妈、爸爸、祖辈或其他家人。
- 扫码绑定设备。
- 设备命名和房间位置设置。
- 家庭成员邀请。
- 成员角色：管理员、监护人、临时查看者。
- 设备解绑、转移和异常离线提示。
- 家庭协作待办：安全事件、打卡审核、任务纠正、奖励兑换申请和兑现提醒可分配给具体照护人。
- 处理记录：记录谁在什么时间处理了什么事项，避免多位家长重复处理或漏处理。

当前家长资料用于通知分发、报告称呼、处理记录和权限判断。首次登录后必须录入：

| 字段 | 是否必填 | 用途 |
|---|---|---|
| 家长身份 | 必填 | 妈妈、爸爸、祖辈或其他家人 |
| 家长称呼/昵称 | 必填 | 报告、通知、家庭协作记录里的显示名 |
| 手机号 | 必填 | 登录、安全验证、找回账号和重要通知 |
| 家庭角色 | 必填 | 管理员、监护人、临时查看者 |
| 头像 | 可选 | 家庭成员识别 |

“我的”里必须提供个人信息和账号安全入口。个人信息支持修改头像、称呼、家长身份和家庭显示名；账号安全只承载更换手机号、查看登录设备和注销账号说明。退出登录不需要藏在账号安全里，放在“我的”页底部作为单行按钮即可；儿童数据导出和删除申请归入隐私与权限。

### 孩子档案

孩子档案用于调整提醒语气、任务时长、学习内容和安全策略，只收集必要信息。

建议字段：

| 字段 | 是否必填 | 用途 |
|---|---|---|
| 孩子称呼 | 必填 | 语音互动、报告称呼 |
| 出生日期 | 必填 | 自动推算当前年龄，用于模板推荐、提醒语气、任务时长、安全等级 |
| 就读阶段 | 必填 | 区分幼儿园、小学、初中或其他阶段 |
| 班级/年级 | 必填 | 幼儿园小班/中班/大班，小学一至六年级，初中七至九年级 |
| 作息时间 | 建议填写 | 起床、吃饭、学习、睡觉提醒 |
| 紧急联系人 | 安全功能必填 | SOS 和异常告警 |
| 教材版本 | 可选 | 后续学习诊断 |
| 兴趣偏好 | 可选 | 故事、陪伴话题 |

性别不建议作为必填项，核心功能不依赖性别。

交互上，年龄不让家长手动估算，改为填写出生日期，由 App 自动推算当前年龄。就读阶段和年级都使用下拉选择：就读阶段包括幼儿园、小学、初中，年级随就读阶段切换选项；班级名称保留手动填写。孩子档案页只负责收集资料，不展示“作息建议”“专注建议”这类中间参数，这些参数应在任务模板、提醒策略和小书包规则里自动体现。首次绑定流程进入孩子档案时，底部显示“继续命名摄像头”；从“我的”进入编辑孩子档案时，不再出现这个引导按钮，只保留保存档案或返回。

### 任务

App 中只保留“任务”一个核心概念，不再拆出另一套流程概念。家长要做的是给孩子安排任务；如果家长从某一天的任务时间轴进入，系统自动带入这一天；如果从普通新建入口进入，则必须先选择任务日期，也可以创建或修改未来日期的任务。

任务可以是单次任务，也可以来自任务模板。睡前洗漱、小书包、晨起提醒、吃饭、家务、作业、阅读、运动、打卡都属于任务，只是任务类型、检测方式和提醒话术不同。

任务日期规则：

- 从日期时间轴点击“继续添加这一天”时，默认带入当前选中的日期。
- 从普通新建入口进入时，不默认日期，家长需要先选择今天、明天或未来某一天。
- 家长可以改为明天、某个未来日期，或设置重复规则。
- 首页只展示当前正在进行、即将开始、异常卡住和需要家长处理的任务。
- 任务页按日期查看：今天、明天、本周、日历。
- 未来任务到日期后自动进入当天任务列表。

任务模板由孩子档案驱动生成。App 在录入孩子出生日期、就读阶段和班级后，自动推算年龄并推荐一组适龄任务模板；家长可以一键启用、删除、改时间、改奖励数量或改提醒强度。

任务模板示例：

| 阶段 | 模板方向 | 示例任务 |
|---|---|---|
| 幼儿园小/中班 | 作息、生活自理、收纳、安全 | 起床穿衣、吃饭、收玩具、睡前洗漱、亲子阅读、陌生人不开门 |
| 幼儿园大班 | 入学准备、规则感、简单家务 | 检查小书包、练习握笔、图书阅读、准备第二天物品、睡前任务 |
| 小学一二年级 | 作业习惯、阅读、小书包整理 | 读书 15 分钟、口算练习、检查小书包、按时睡觉 |
| 小学三至六年级 | 专注学习、运动、家务、错题 | 作业专注 25 分钟、错题订正、英语朗读、运动 30 分钟、整理房间 |
| 初中 | 自主计划、复盘、运动、屏幕边界 | 作业 45 分钟、错题复盘、明日计划、运动、手机/平板收纳 |

小书包不是单纯“带书”。幼儿园阶段默认是水杯、备用衣物、园服、午睡用品、活动材料、通知回执等入园物品；小学和初中阶段才根据课程表、学校要求和第二天安排生成课本、练习册、作业本、文具、运动服、美术材料等准备项。家长可以在孩子档案里设置“书本通常放家里 / 部分放学校 / 有储物柜 / 书包留校 / 只按老师通知准备”，避免系统把所有孩子都当成同一种上学方式。小书包页面也要随学段切换操作方式：幼儿园强调老师通知和每日固定物品，小学强调课程表与临时材料，初中强调孩子自查、储物柜和按明日课表准备。

小书包规则的作用是控制“生成什么、少提醒什么、什么时候提醒”：

| 学段 | 规则 | 作用 |
|---|---|---|
| 幼儿园 | 按老师通知 | 只把老师通知、园所群消息和临时活动变成清单，避免每天出现无关物品 |
| 幼儿园 | 每日固定 | 每天固定提醒水杯、备用衣物、园服和午睡用品 |
| 幼儿园 | 临时活动 | 平时少提醒，遇到手工、春游、运动会等活动时重点生成材料清单 |
| 小学 | 部分书放学校 | 不把留校课本加入晚间清单，只提醒需要带回家的作业本、练习册和临时材料 |
| 小学 | 每天带回 | 每天晚间检查课本、作业本和文具，适合学校要求书本每天带回的情况 |
| 小学 | 有储物柜 | 把清单分成“柜内保留”和“明天带回”，只在需要补充或带走时提醒 |
| 初中 | 只带明日 | 只按第二天课表生成学科资料，减少书包重量和家长逐项检查 |
| 初中 | 有储物柜 | 默认把常用资料留在学校，只提醒错题本、作业材料和需要带回签字的内容 |
| 初中 | 按老师通知 | 不强依赖课程表，主要根据老师通知、作业要求和临时活动生成清单 |

任务字段：

| 字段 | 示例 |
|---|---|
| 任务名称 | 数学作业 |
| 任务类型 | 学习、家务、吃饭、洗澡、睡眠、打卡 |
| 日期/重复 | 时间轴进入默认选中日期；普通新建需先选今天、明天、指定日期或重复规则 |
| 开始时间 | 19:00 |
| 预计时长 | 25 分钟 |
| 休息规则 | 25 分钟学习 + 5 分钟休息 |
| 积分 | 完成 +5 |
| 检测方式 | AI 判断、家长确认、手动完成 |
| 提醒方式 | 摄像头语音、App 推送、仅记录 |
| 证据要求 | 无、截图、短视频、家长确认 |
| 模板来源 | 手动创建、系统推荐、家长自定义模板 |

                         v               v
                      delayed         paused

家长端操作：

- 新建任务。
- 批量创建一周任务。
- 暂停、延后、跳过、完成。
- 查看任务开始证据和提醒次数。
- 对 AI 判断结果进行纠正。
- 查看任务完成证据，例如作业桌面截图、家务前后对比、打卡视频。
- 对任务结果进行确认、驳回或改判，纠正结果进入日报和奖励计量流水。

### 任务证据与确认

任务证据用于降低误判，也让家长知道孩子不是“被 AI 扣分或加分”，而是有可解释的完成依据。

适用场景：

- 作业：截图、专注轮次、离座次数、求助记录。
- 家务：整理前后截图或短视频。
- 打卡：照片/视频素材和家长审核结果。
- 睡前任务：洗漱、检查小书包、上床等任务节点。

家长端能力：

- 查看证据缩略图、时间、触发规则和置信度。
- 一键确认完成、驳回、改为部分完成。
- 撤销自动加分或发起手动补分。
- 标记误判原因，用于后续规则优化。

### 专注计时

专注计时服务于学习和练习场景。

默认模式：

- 25 分钟学习 + 5 分钟休息。
- 低龄儿童可选 15/5 或 20/5。
- 家长可配置长休息。
- 支持任务中途暂停和延后。

App 展示：

- 当前专注轮次。
- 剩余时间。
- 是否离座。
- 是否出现坐姿提醒。
- 休息是否结束。
- 本次任务是否超时。

### 睡眠与晨起

睡眠与晨起用于回应家长对“几点睡着、有没有睡、早上能不能叫起床”的需求。首版只做家长端可理解的基础记录，不做医疗化判断。

页面内容：

- 今晚睡前任务状态。
- 上床时间、疑似入睡时间、起床时间。
- 夜间醒来、长时间未睡、异常声音提醒。
- 晨起闹铃状态：待响、已响、已延后、已起床。
- 睡眠日报入口，展示入睡时长、夜醒次数和作息趋势。

家长端操作：

- 设置睡觉时间、起床时间、午睡时间。
- 设置晨起提醒音量、延后次数和是否需要家长确认。
- 设置夜间免打扰，只保留安全事件和异常声音通知。

### 实时看护

实时看护用于家长主动查看孩子当前状态。

页面内容：

- 实时画面入口。
- 设备在线和隐私状态。
- 音频通话按钮。
- 截图按钮。
- 云台方向控制。
- 常用视角预置位：书桌、床、门口、玩具区。
- 最近事件列表。
- 事件回放入口，查看安全、任务、睡眠、打卡等事件的短片或截图。

隐私要求：

- 家长查看实时画面时，App 要提示设备端会显示工作状态。
- 隐私模式开启时，实时看护入口应明确不可用或受限。
- 家长可以设置“只保存事件截图，不保存连续录像”。

### 报告

报告页让家长快速理解孩子一天和一周的状态。

日报内容：

- 今日摘要。
- 今日任务完成情况。
- 任务完成/未完成/超时。
- 坐姿、专注、离座、休息记录。
- 积分变化。
- 学习求助摘要。
- 对话摘要。
- 睡眠与晨起摘要。
- 小书包完成情况。
- 任务证据和家长确认记录。
- 安全和异常事件。
- 成长时刻精选。
- 明日建议，最多 1-3 条。

周报内容：

- 本周任务完成趋势。
- 专注时长和按时开始趋势。
- 坐姿提醒和离座趋势。
- 高频学习求助类型。
- 作业依赖风险：是否频繁问同类题、是否跳过思考直接求助。
- 睡眠趋势：入睡时间、起床时间、夜醒趋势。
- 家庭协作处理情况。
- 积分变化。
- 家长需要关注的 1-3 个问题。
- 下周建议目标。

报告页原则：

- 先给结论，再给明细。
- 不制造焦虑，不使用“落后、失败、糟糕”等评价词。
- 支持展开查看证据截图、事件时间线和对话摘要。

### 积分与奖励

积分与奖励系统是家长用来正向激励孩子的工具，家长可以选择用积分、小红花或小星星作为计量单位。

功能包括：

- 今日奖励计量总览。
- 奖励计量流水。
- 奖励规则。
- 兑换奖品。
- 家长手动调整。
- AI 自动加分后的撤销入口。
- 阶段规则：家长可以选择计量类型和阶段阈值；计量类型包括积分、小红花、小星星，默认是积分；阶段阈值默认 10，可调整。10 积分、10 朵小红花或 10 颗小星星都可以是一个阶段，但积分和小红花/小星星不是互相换算关系。
- 奖励商店：家长设置奖品名称、所需数量、兑换限制和有效期；已添加奖品可按 App 常规右滑操作修改或删除。
- 家长主动兑换：不需要孩子先申请，家长可以随时在奖励商店选择奖品并兑换，系统扣除对应数量，写入流水和兑现记录。
- 语音兑换申请：孩子可对摄像头说“我想换奖励”或“我想换周末户外活动”，摄像头先检查当前计量余额和家庭规则，只说“我帮你问妈妈/爸爸”，再生成家长待确认事项。
- 奖励确认与兑现：首版没有孩子端 App，但要保留家长确认/审核流；家长可同意并立即兑现、同意但稍后提醒、暂不兑换或取消申请。真正兑换时必须扣除对应数量。
- 兑现记录：记录奖品、扣除数量、兑换前后余额、申请来源、操作人、确认结果和兑现状态。
- 奖励模板：App 根据年龄和就读阶段推荐奖励池，家长可启用或修改。
- 孩子端 App 预留：未来孩子端 App 可以展示家长开放的奖励商店、提交兑换申请、查看审核状态；所有兑换仍必须由家长确认。

原则：

- 少扣分，多鼓励。
- 自动扣分默认关闭。
- 兑换奖励由家长设置，摄像头和未来孩子端 App 都不能直接承诺孩子奖励，只能转交申请或展示家长已开放的规则。
- 达到阶段阈值只提醒家长，不自动兑换、不自动清零；是否兑换、兑换什么、是否继续累积都由家长决定。
- 奖励不只绑定学习，也可以绑定收纳、按时起床、按时睡觉、独立完成任务等习惯。
- 小龄儿童优先用即时表扬、贴纸、亲子活动；小学阶段可以用积分兑换小特权；初中阶段更适合用自主权、运动/兴趣活动、周末安排选择权。
- 不建议把已获得的奖励计量随意扣回；严重问题优先交给家长确认和沟通。
- 习惯稳定后，App 应建议家长降低外部奖励权重，把奖励从物质转向表扬、信任和自主选择权。

奖励模板示例：

| 类型 | 示例 | 适合阶段 |
|---|---|---|
| 即时正反馈 | 表扬语、星星、徽章、今天完成图 | 幼儿园、小学低年级 |
| 亲子活动 | 亲子游戏 15 分钟、一起读书、周末公园 | 幼儿园、小学 |
| 小特权 | 选择晚饭后故事、选择家庭游戏、周末活动投票 | 小学、初中 |
| 兴趣支持 | 画材、球类时间、模型/手工材料 | 小学、初中 |
| 物质奖励 | 小零食、小文具、小玩具 | 谨慎使用，需家长设置上限 |

### 成长时刻与事件回放

成长时刻用于保留值得回看的积极片段，事件回放用于帮助家长快速判断发生了什么。

内容包括：

- 第一次独立完成任务。
- 连续专注、按时开始、主动整理、睡前任务完整完成。
- 家长标记的重要照片或短视频。
- 安全事件、离座事件、打卡事件的回放入口。

原则：

- 默认只保存精选片段和事件证据，不保存全天连续录像。
- 家长可以收藏、删除、分享或隐藏某个成长时刻。
- 成长时刻优先强化积极行为，不把孩子的失误做成公开展示。

### 打卡助手

打卡助手用于学校、兴趣班或家庭任务的照片/视频素材准备。

MVP 范围：

- 创建打卡任务。
- 接收摄像头采集的照片或视频素材。
- 家长审核素材。
- 保存到相册或分享给其他 App。
- 记录打卡完成状态。

首版不做第三方学校平台自动提交。

### 对话与人设设置

家长可以管理孩子和摄像头的互动边界。

功能包括：

- 设置孩子称呼。
- 设置摄像头唤醒名。
- 选择原创声线。
- 设置自由聊天单次时长。
- 设置每日总聊天时长。
- 设置故事、音乐、音频通话的可用时段。
- 设置提醒频率、冷却时间和免打扰时段。
- 开启或关闭普通闲聊摘要。
- 查看学习、情绪、安全等分类对话摘要。
- 开启逐字记录时必须有明确提示。

首次使用里的“摄像头命名”只做轻量说明：告诉家长默认有作业模式、睡前模式和记录策略，不在 onboarding 里强迫家长配置。真正可配置入口放在“我的 > 设备与规则 > 对话与人设”，家长之后可以调整自由聊天单次时长、每日总时长、睡前限制、作业模式限制和记录策略。

对话记录默认策略：

| 类型 | 默认展示 |
|---|---|
| 普通闲聊 | 主题摘要和时长 |
| 作业辅导 | 题目、引导过程、结果摘要 |
| 情绪表达 | 摘要和关注标签 |
| 安全事件 | 原文、音频片段、事件证据 |

互动边界默认规则：

- 作业模式中只允许任务相关问答。
- 睡前模式中不主动开启长时间自由聊天。
- 免打扰时段内只保留安全告警、晨起闹铃和家长主动通话。
- 孩子频繁问同类题时，日报中标记“可能依赖 AI 求助”，建议家长关注。

### 安全告警

安全模块用于高优先级事件处理。

页面内容：

- SOS 事件。
- 陌生人或敲门提醒。
- 危险区域提醒。
- 异常声音提醒。
- 家长异常求助。
- 安全区域规则：门口、厨房、窗边、阳台、楼梯等。
- 紧急联系人。
- 事件处理状态：待处理、已联系、已解决、误报。
- 处理人和处理时间。

告警流程：

1. App 收到安全推送。
2. 进入安全事件详情。
3. 查看事件摘要、截图、音频或短视频。
4. 一键发起音频通话。
5. 指派或记录处理人。
6. 标记处理结果。
7. 必要时通知第二联系人。

### 隐私与权限

隐私设置是家长端的基础能力。

功能包括：

- 隐私模式开关。
- 远程查看提示设置。
- 对话记录保存策略。
- 照片、视频、报告删除。
- 家庭成员权限。
- 儿童数据导出和删除入口。
- 推送通知开关。

订阅入口建议放在“我的”顶部的家庭账户卡下方。订阅页需要明确三件事：

- 当前套餐与权益：基础版、米拉会员、家庭高级版。
- 基础功能边界：任务提醒、实时看护、本地日报、隐私控制等核心能力不应被订阅锁死。
- 会员增强项：云端长期报告、高级趋势、更多人设/声线、题目辅导额度、多孩子/多设备、合作内容包。
- 费用与记录：续费状态、到期时间、发票/订单、取消或降级说明。

## MVP 范围

当前 V1 聚焦家长端最小闭环，而不是一次性实现所有长期功能。

已完成或当前阶段可验收的 V1 能力：

1. welcome/onboarding、手机号验证码登录、refresh token 登录态保持。
2. 首次设置流程：家长身份、设备绑定入口、Wi-Fi 配网、绑定成功、孩子资料、紧急联系人。
3. 主 Tab：首页、任务、看护、告警、我的。
4. 首页核心看护状态、今日任务摘要、设备/摄像头基础状态、积分奖励轻入口。
5. 任务列表、任务详情、任务完成、家长确认、驳回确认。
6. 积分账户、积分流水、任务确认发放积分、家长手动调整。
7. 奖励列表、奖励详情、兑换、取消兑换、手动标记兑现。
8. 实时看护基础入口：camera health、runtime、snapshot/stream 边界；真实流不可用时降级展示。
9. 我的/设置页：家庭、孩子、设备基础信息，积分/奖励、用户协议、隐私政策入口。
10. 后端 V1 边界：SmsProvider 抽象、prompt registry / AI config、firmware/OTA reserved API。

V1 只做结构预留或轻量摘要，不实现完整业务闭环：

- 告警中心只保留普通摘要和处理状态，不实现安全事件详情和复杂事件流。
- 安全区域、安全事件、SOS 完整处理、地理围栏不进入 V1。
- 打卡、日报/周报、成长时刻、订阅、支付、复杂家庭审计留到后续版本。
- 子端奖励申请只保留状态/API 边界，不做完整孩子端 UI。
- 真实短信供应商、真实 OTA 执行、复杂 AI eval 后台 UI 暂不实现。

## 隐私与合规原则

- 收集、使用、上传儿童音视频前必须获得监护人授权。
- 普通对话默认展示摘要，不默认展示全部逐字记录。
- 家长开启逐字记录时，App 必须明确提示用途和保存周期。
- 家长可删除照片、视频、对话摘要、逐字记录和报告。
- 家长可删除成长时刻和任务证据，安全事件证据按合规策略保留最小必要内容。
- 家庭成员按角色授权，避免非监护人查看敏感数据。
- 远程查看、通话、录像和记录模式需要清晰的 App 提示。
- 隐私模式开启后，实时看护和记录入口必须明显受限。
- 睡眠、成长时刻和家庭协作记录都应支持分级权限。
